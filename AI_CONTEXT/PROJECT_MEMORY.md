## 1. 项目是什么

Always Game 是一款低资源消耗、持续运行的挂机战略游戏。玩家以全局视角扮演一个逐步成长为“大统合联邦”的**单一主权中央政府**：从灾后行星上的小型存续共同体出发，经聚居、区域网络、母星统合、太阳系开发、星际扩张，最终面对银河尺度的治理与终局危机。

核心体验不是逐人、逐格、逐建筑微操，而是：玩家设定国家方向、政策、科研与工程优先级、安全底线和重大抉择；持续模拟负责执行、失败、维护、人口流动、社会反应与历史后果。

## 2. 世界观核心目标

- 让技术进步有物质、制度与人的代价，而非单纯数值升级。
- 让“统一”既有中央调配能力，也有执行摩擦、地方反馈、战争创伤、转岗与权利问题；它不是松散邦联，也不是无代价征服。
- 让编年史是固定宏观难题与文明锚点，玩家可以改变抵达速度、路线、伤亡、社会结构及局部结局。
- 让普通人的日常始终可见：水、食物、工时、住房、教育、医疗、迁徙、家属居留、伤亡、文化与申诉必须成为宏观选择的反馈。

## 3. 创作理念与叙事风格

### 创作理念

1. **因果优先。** 技术必须经由“技术 → 产业/设施 → 社会组织 → 政治制度 → 日常生活”产生影响。
2. **能力先于奇迹。** 理论、原型、可复制、规模化与制度化是不同阶段；科研抢跑不能跳过材料、能源、维护、人才、物流和工程验证。
3. **代价可追溯。** 军事、工业、科研、生态修复和福利都应有机会成本、维护负担与延迟后果。
4. **统一但不扁平。** 中央拥有主权与战略能力；地方能执行、反馈、申诉并保留生活方式选择，但不能变成并列国家。
5. **系统先于剧本。** 剧本用于验证规则、补完世界与提供内容，不得写死通用系统。

### 叙事风格

克制、具体、有历史感。事件写“发生了什么—影响了谁—能做什么”；科技写原理、能力、条件与限制；工程写看得见、可损坏、可维护的实体；国策使用统一政府的正式方针口吻。避免 AI 解释腔、抽象开发术语和只讲宏大口号的叙事。

## 4. 已确定的重要设定

### 玩家、政府与自治

- 玩家是最高战略执政权，不是殖民地领班或战术指挥员。
- 政体演化方向为：工程师委员会 → 城邦中央政府 → 大陆统合政府 → 大统合联邦中央政府 → 银河统合政府。
- “联邦”是超大疆域的行政形式，不是独立主权国家的联盟。中央掌握军队、外交、货币、税收、人口登记、战略资源、跨区司法、国家计划、生态红线及战略科研。
- 地方只保有有限的现场执行、服务反馈、例外申报、文化/教育语言与非战略生活选择；没有独立军队、外交、货币、战略资源处置权、退出权或对国家计划的否决权。

### 余烬与大历史

- 原始世界为灾后类地行星“余烬”：气候崩坏、病原灾难和轨道打击留下污染、水土破坏、遗产技术碎片和低人口社会。
- 默认宏观主线从灾后重建走向 580 年母星大统合，继而经历太阳系（580–780）、摇篮星团（780–1080）、区域星区（1080–1400）、旋臂走廊（1400–1850）、银河联邦（1850–2250）与终局危机（2250–2450）。
- 星际扩张也受工程、事故、检疫、航道、自治、救援、代表权与环境成本约束；不允许“一项科技立即解决一个星系”。

### 游戏循环与指标

- 游戏按日持续运行；仅玩家主动暂停。普通事件、报告、科研和工程完成不应把挂机强行切成回合。
- 玩家操作：国策、当前政策、科研槽、工程槽、安全姿态、真正改变路线的重大抉择。科研与工程各可开启自动续接。
- 长期状态使用九项核心指标：日常保障、工务能力、可用能源、研究能力、统筹能力、运输与补给、防卫能力、共同体协作、土地与环境。
- 具体物料不是无限累积的顶栏库存，而是工程投入、维护、事件原因与地区特性；早期以 LDU（维持共同体一天的标准消耗），国家阶段以 NDU（维持国家一天的标准消耗）表达尺度。

### 科技、工程与政策

- 每历史阶段目标目录：1,000 科技、1,000 工程、20 个政策家族（每家族随能力分为 early/capable/institutional 三版）。
- 科技树按十领域构成 50 主干突破、750 路线分支、200 分级完善；主干构成跨领域有向无环图。
- 科技只授予能力；工程是有选址、施工、试运行、投用和维护的实体结果；政策是有对象、期限和代价的行政行动；国策是长期资源倾斜。
- 重大技术不仅需要知识前置，也可能需要已投用工程作为现实能力证明。

### 世界生成与地图

- 通用世界遵守因果顺序：行星参数 → 地壳/海盆 → 构造地貌 → 水文 → 气候 → 生态/资源潜力 → 玩家工程增量。
- 使用可重建的二十面体 L5 球面网格；地点、工程与网络使用稳定地理引用，不能依赖屏幕坐标或贴图名称。
- 自然地理、工程模块、某局工程结果、视觉层分开保存；缩放只改变展示精度，不能重新生成山脉、海岸或河流。
- 道路和网络必须先有真实端点与被选择的开发目标，再依据坡度、水系、海陆、风险、技术和建设能力规划；不预铺“最优道路”。

## 5. 剧本与通用系统的边界

“第 07 号—翡翠河谷—旧渡口”是 **Legacy Valley Fixture（旧河谷测试夹具）**：可用于回归测试、早期数值与文案样本，也可作为可选剧本，但不得作为通用引擎、世界生成、科技前置、工程选址或默认战役的硬编码输入。

通用层必须分为：产品/世界硬设定、自然世界模板、通用内容目录、战役模板、剧本夹具、呈现与叙事。显示名、中文标题、旗帜和贴图均不是逻辑主键。

## 6. AI 工作原则

1. 先确认权威来源和当前状态，再提出或修改内容。
2. 将“已确认”“暂定”“旧稿/样例”“尚未实现”明确分开，不把计划写成已完成事实。
3. 新设定必须说明技术前置、产业承载、社会代价、政治经济影响和普通人生活变化。
4. 新系统先定义对象、关系、状态、输入输出和验收，再填大量内容或做界面美术。
5. 玩家可见文本必须遵守 R6 文案分类与口吻；内部 ID、债务、权重、槽位等开发语言不得直接暴露给玩家。
6. DeepSeek 仅可承担已冻结规格的代码填充、数据录入、验证和测试；不得自行决定世界观、文案、视觉、交互、数值或范围。

## 7. 禁止破坏的设定

- 不把游戏退回三人殖民地、逐格建造或逐人工作分配主循环。
- 不把大统合联邦写成地方可独立外交、拥有战略军队或随时退出的松散邦联。
- 不以“研究完成”跳过产业化、实体设施、维护、人才、后勤与制度化。
- 不让科技、工程、政策沦为孤立的永久百分比加成。
- 不以戏剧性为由让战争、统一、火星宜居化、虫洞、行星改造或超大工程无代价即时完成。
- 不用固定河谷名称、坐标、项目 ID 或资产名驱动通用系统。
- 不让视觉层、AI 文案或测试夹具反向制造或修改世界事实。
