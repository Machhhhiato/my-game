# 工程与科技描述风格来源摘要

## 1. 这份文件是什么

用户在 `M0-S003-U036` 提供了另一个对话整理出的讨论与总结，并要求在 `M0-L1-105` 后增加一个独立环节，统一后续工程与科技的描述风格。

本文件只保存从附件中提炼出的通用写作规则，不保存小说章节、原文段落、专有名词或仿写文本。它是 `M0-L1-106` 的讨论输入，不是已经接受的项目规格。

## 2. 希望得到的味道

一句话方向：`不要写邪恶的科技，要写通过验收的科技。`

这里的重点不是把科技写成故意害人的机器，而是先让技术本身可信，再让制度、指标、成本、程序或宣传把一个明显荒诞的结果解释成“合格”“先进”或“值得推广”。

### 技术部分必须站得住

至少根据使用位置写清其中必要的信息：

- 它解决什么具体问题；
- 使用什么原理、材料、设备或工序；
- 对哪个阶段生效；
- 需要什么地点、人员、物资、能源或维护；
- 有什么边界、故障和备用办法；
- 上线前后，玩家能直接看见什么变化。

删除最后的讽刺转折后，正文仍应像一份可信的工程资料，而不是先写笑话再补技术名词。

### 荒诞主要来自制度怎样解释结果

可讨论的来源包括：

- 把缺陷重新命名为功能；
- 改统计口径，而不是解决问题；
- 因成本或产量达标而压过安全缺口；
- 关闭警报、降低标准或把风险移出报表；
- 程序完整，所以结果被宣布合法；
- 崇高目标最后落到很小的行政或采购理由；
- 把人、城市或生态改写成可归档的零件和资产；
- 伦理审批本身成为荒诞环节。

这些只是手法库，不能每条都使用同一种反转。

荒诞也可以来自多个部门各自正确完成了工程、审计、法务、采购或宣传职责，但这些局部正确组合成了荒诞结果；不需要把任何一方写成主动邪恶的反派。

## 3. 可使用的文体载体

不建立一个虚构文明的统一档案口吻。工程与科技可以根据内容使用不同载体：

- 产品说明书与操作手册；
- 安全通告、故障通知和维修单；
- 研发日志、试验记录和验收报告；
- 采购文件、成本审计和预算说明；
- 专利摘要与技术标准；
- 伦理审批、城市条例和行政决定；
- 新闻稿、公开声明和事故复盘。

载体必须服务于该科技实际发生的流程。不能为了显得高级而堆叠公文词。

第一座前哨首次进入一个阶段时，可以使用完整负责人报告；第二座复制和其他重复建设的普通进展只进入短日志。只有新事实、真实选择、阻断和完成验收才主动提示，避免为了保留风格而反复打断自动运行。

## 4. 叙述规则

- 世界内的说话者保持冷静、认真和自洽，不替玩家解释笑点。
- 最后的反转应短、具体、像事实记录；删掉它，技术正文仍然成立。
- 先让玩家看懂解锁了什么、影响哪一段、需要什么实体，再呈现风格。
- 工程和科技不提供脱离机制的额外故事效果；所有数字必须与规格和运行状态一致。
- 同一批内容要有轻重变化，不能每项科技都死人、屠杀或把机构写成卡通反派。
- 不使用网络热梗、作者吐槽、连续感叹号或用抽象大词遮住实际信息。

## 5. 后续层级怎样分工

| 层级 | 负责 | 不负责 |
|---|---|---|
| 第一层 `M0-L1-106` | 冻结信息字段、载体范围、风格边界、强度分级、长度范围和验收办法 | 不写具体负责人、完整事件或最终正文 |
| 第二层 `M0-L2-201` | 选择具体机构、人物处境、事件因果和使用哪种文体载体 | 不新增机制和数值 |
| 第三层 `M0-L3-301` | 写最终名称、正文、按钮和提示，只引用第一层冻结且第四层审计确认的动态变量 | 不改变结构、结果或玩法，不新建变量含义或数值 |
| 第四层 `M0-L4-010` | 只读确认变量、状态、界面和存档落点 | 不修改代码，不替上层重写内容方向 |
| 第四层实施任务 | 按审计结果把文字绑定到真实运行状态与变量 | 不改变已接受文案、变量含义或机制 |

## 6. L106 必须逐项讨论的内容

1. 每条科技或工程描述固定显示哪些玩法信息；
2. 哪些载体适合科研、建设、事故、验收和维护；
3. 轻度、中度、重度以及完全严肃内容各占多少，是否需要按类别而非全局配比；
4. 普通科技、关键科技、阶段报告、重复日志和时代级科技或大型工程各用多长；
5. 哪些反转手法可以复用，怎样避免同一个笑点反复出现；
6. 重度内容的边界，怎样避免把死亡和残酷变成廉价装饰；
7. 如何检查“去掉风格仍能看懂机制”和“去掉末句仍是可信工程资料”。

附件中出现过轻度 50%、中度 35%、重度 15%，以及若干字数范围。这些都只作为来源提案保存，尚未接受；`M0-L1-106` 还必须讨论是否保留一部分完全严肃的内容，以及不同内容类别是否应该使用不同配比。

## 7. 后续结构字段候选

以下字段留给 `M0-L1-106` 取舍，不在本文件冻结：

- 名称与玩法对象；
- 解锁内容与作用阶段；
- 所需实体、地点、人员、物资、能源和维护；
- 改变的变量与明确不改变的变量；
- 基础路线、升级路线和故障后的备用路线；
- 文体载体、说话者或责任机构；
- 风格强度与反转手法；
- 不能改写的世界事实；
- 允许引用的动态数值与状态变量。

验收时至少检查：玩家能迅速看懂解锁、阶段和需求；移除风格后机制仍完整；移除末句后正文仍可信；科技只有在实体部署后生效；预计时间的变化方向和实际结算一致。
