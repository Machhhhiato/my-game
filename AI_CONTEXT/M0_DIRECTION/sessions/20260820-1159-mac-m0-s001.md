`求生取舍 → 接纳更多人 → 暴露维护债务 → 将生存能力投射到地图外缘`

建议设置 7 次核心决策：

| 阶段 | 核心决策 | 方案方向 |
|---|---|---|
| 水源危机 | 首轮勘察优先级 | 水线、住处、维修残件 |
| 水源危机 | 长期供水方式 | 快速高维护、较慢高韧性、低物资高劳动 |
| 避难者安置 | 接纳方式 | 立即接纳、分批转移、原地支援 |
| 避难者安置 | 安置布局 | 驻地集中、修复旧区、靠近作业区分散安置 |
| 工具危机 | 当前故障处理 | 拆件应急、暂停建设抽调维修、冒险低效运行 |
| 维修瓶颈 | 长期维修制度 | 中央工场、维修轮班、外缘转存网络 |
| 高地前哨 | 路线与前哨方案 | 短陡直达、可靠绕行、补给点分段推进 |

- 地图上出现不同设施、路线或聚居布局；
- 人员、输入、维护和工期发生变化；
- 普通人的供水、劳动、住处、健康或信任发生变化；
- 下一阶段获得不同机会，而不是简单的“好结局/坏结局”。

## 二、每场聊天保存什么

每个 session 文档保存：

- 用户可见的原始消息，逐字记录；
- 助手可见的过程说明和最终回答；
- 事实与证据来源；
- 当前采用的假设；
- 考虑过的方案与取舍；
- 已确认、待确认、否决、推迟的内容；
- 本场结束摘要和下一步。

每轮使用固定 ID，例如：

```text
M0-S001-U001    用户消息
M0-S001-A001    助手回答
M0-S001-R001    对应的决策理由记录
```

“思路”保存为可审计记录：

```text
证据 → 假设 → 候选方案 → 利弊取舍 → 当前结论
```

不会保存系统隐藏提示、隐式思维链、完整工具噪声或密钥；工具产生的重要事实会被整理成证据记录。这样可以复现判断过程，又不会把敏感信息永久写进 Git 历史。

## 三、ACTIVE 接续卡

`ACTIVE.md` 必须很短，建议不超过 200 行，包含：

- 当前目标；
- 已确认的 3–5 项决定；
- 尚未确认的最多 3 个问题；
- 被明确否决的方向；
- 唯一下一步；
- 不允许扩展的范围；
- 当前分支、远端提交、最后 session 和 turn ID；
- 当前写入设备：`mac` 或 `windows`；
- 下一场聊天可以直接使用的开场指令。

任何新聊天只需要先读这张卡，不需要加载全部历史。

一个“可独立运行的前哨”应具备：

- 明确资源地点；
- 生产或采集设施；
- 当地加工与仓储；
- 人员或自动化设备；
- 通往总部的真实运输路线；
- 维护、备件和安全保障；
- 可观察的日产量、库存、运输量和中断原因。

独立运行是“日常无需玩家逐次点击”，不是永不维护。水、农田和能源可以在条件稳定时持续生产；废墟与矿藏具有储量和品位，会逐渐下降，需要继续勘探和占领新地图。这种衰减不是强迫匮乏，而是自然推动扩张。

## 首建成功后获得“标准工程包”

工程包不是一个抽象的“建造速度 +20%”，而是已经验证过的：

- 适用土地和资源条件；
- 设备与材料清单；
- 清理、施工和测试顺序；
- 试产参数、维护规范与运输方案；
- 已训练的工程队和生产经验。

后续同类前哨分三种情况：

1. **完全符合工程包条件**：玩家授权后，系统自动完成勘测、清理、施工、测试和试产。
2. **存在轻微差异**：系统进行短期工程适配；成功后扩大工程包的适用范围。
3. **出现从未处理过的条件**：重新成为需要玩家协调的工程变体，例如首次在泥地施工或处理高污染废墟。

自动复制仍然真实消耗人力、物资、时间和运输能力。系统只在土地不适用、资源将跌破底线、人力严重冲突或测试发现新问题时打断玩家；经验消除的是重复管理，不是客观成本。

## 地图骨架：区域、候选地块和交通线

M0 不需要做成逐格整地模拟。我建议采用“区域节点 + 少量候选工程地块 + 交通连接”，每个地块同时拥有多层属性：

| 层级 | 示例 |
|---|---|
| 地貌与地表 | 平地、丘陵、山地、泥地/湿地、沙地 |
| 水文 | 河边、湖边、海岸、地下水、洪水风险 |
| 资源与覆盖物 | 肥沃土层、矿脉、城市废墟、可回收构件 |
| 工程与交通 | 可用面积、坡度、地基、污染、道路、距总部距离 |

每项工程再定义三类条件：

- **硬性条件**：不满足就不能建，例如矿山必须有矿脉；
- **可工程化条件**：可以用排水、清障、护岸、道路或地基工程解决；
- **效率与风险条件**：影响工期、产量、维护和运输，但不直接禁止建设。

因此农田需要肥沃土地、可接受坡度和水源，不能直接塞进山地或城市废墟；废墟回收必须依附城市遗址；取水工程必须连接可靠水源。底层数据也不应只有一个互斥的 `terrainType`，而应让同一地块同时携带地貌、资源、风险和交通标签。

## 有限人力：用排程制造管理挑战

M0 先用三类能力池就够了：通用生产与物流、工程与维护、科研与勘测。人力被分配到总部生命线、日常资源生产、维护物流、普通科研、探索和工程建设。

每个岗位或项目显示三档需求：最低人力、标准人力、加速人力。玩家还可以设置：

- 各系统最低值守人数；
- 食物、水、能源和备件的安全库存天数；
- 项目优先级与最大投入；
- 需要保留的机动人力；
- 是否允许系统自动错峰。

这样玩家可以先积累储备，再开启一段“集中建设窗口”，把科研和工程人力压到首建项目；阶段结束后，系统自动恢复正常配置。人力不足首先导致工期延长、产量平滑下降、维护积压或试产不稳，不会立刻跳成饿死人或设施爆炸的二极管结果。

## 四层共同使用一份“白话设计规则”

每项玩法都必须先回答下面八个问题：

1. 什么时候发生？
2. 玩家在画面上看见什么？
3. 玩家能点什么、选择什么或调配什么？
4. 要花多少人、材料和时间？
5. 系统按什么条件判断可以或不可以？
6. 成功后地图、建筑或数字发生什么变化？
7. 失败后如何暂停、补救、换方案或回收？
8. 什么时候可以自动进行，什么情况会暂停并叫玩家处理？

少一项，就不能交给下一层。每项设计还必须有一个带临时数字的实际例子；数字以后可以平衡，但现在必须能看懂怎么玩。

> 玩家协调人力，完成前哨建设闭环。

> 废墟清理需要 8 人工作 3 天。供水至少需要 4 人值守，普通科研正在占用 3 人。玩家可以暂停普通科研，把这 3 人调去废墟；清理会按时完成，但这 3 天科研不增长。
