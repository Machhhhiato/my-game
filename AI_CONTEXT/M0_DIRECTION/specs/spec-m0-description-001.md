# SPEC-M0-DESCRIPTION-001 · M0 工程与科技描述结构、风格与总规格冻结

## 1. 本规格决定什么

本规格只决定工程、科研、设备、阶段报告、维修和制度类文字怎样组织。科研候选卡先服务快速比较，完整正文再解释技术与世界内情况；需求、时间、阻断和实时状态放在真正负责这些信息的项目页或状态页，不能把所有底层字段挤进一张科研卡。

本任务不写具体负责人的完整故事，不写最终科技正文，不修改已经接受的机制、数字和结果，也不修改游戏代码。只有本规格逐项被用户接受，并最终整体接受后，才可以把 `overall_spec_frozen` 标为 true。

## 2. 已接受输入与不能改动的事实

- 科研完成只解锁图纸、方法、工程或制造条件，不直接生成设施、设备、产量、库存或地图情报。
- 实体能力必须经过制造或修复、运输、部署、标定、配人、供能和维护中实际需要的环节，才对指定阶段生效。
- 第一座前哨的七个历史节点仍可追溯，但每个首次节点只用一至两句世界事实，不固定回答机制字段或下一步；没有真实选择时不暂停工程。
- 第二座复制与重复建设不再生成逐阶段叙事；正常完成只留一句建成记录。新事实、真实选择和阻断按自身事实记录，并继续遵守既有主动提示规则。
- 玩家侧科技只有未研发/已研发，工程只有在建/已建成；进行中只显示进度、已投入物资和占用人力。部署预计、前后预计耗时与完成快照只留底层模型，不作为玩家展示。
- 所有人员、物资、工作量、地点、设备状态、暂停原因和恢复条件都引用已接受的真实状态，不新增“文案专用”变量或效果。
- 来源附件只提供通用规则：技术本身可信，荒诞主要来自制度怎样解释结果；不复制或仿写小说原文、章节与专有名词。

### 6.2 当前正文边界

- 正文只写世界内部存在的设备、工艺、试验、使用和制度后果，不出现“玩家、本科技、解锁、效果、前置条件、工程页面”等系统外语言。
- 世界内参数可以出现，例如公差、温度、连续运转时间和报废件数；`+5%`、科研工作量、内部等级和状态字段不能混入正文。
- 卡片效果负责告诉玩家研究后得到什么；工程页只显示进度、已投入物资和占用人力，其他地点、时间、阻断与恢复条件继续由底层模型负责；正文不重复系统显示。
- 删除制度性结尾后，前面的技术过程仍必须可信；制度荒诞来自验收、统计、程序或成本怎样解释结果，而不是技术本身故意失效。

## 8. 第四项提案：原页面、日志和一次通知

### 8.1 只保留三个地方

1. `原页面`：玩家想看当前情况时，回到对应科技、工程或设施页面。科技显示未研发/已研发和进度；工程显示在建/已建成、进度、已投入物资与占用人力；设施显示自身当前运行情况。

## 9. 第五项提案：去重不是换机构名，而是换荒诞发生的地方

### 9.1 第二行先回答三个问题

第二层或第三层写第二行以前，先在草稿里回答三个不向玩家展示的问题：

1. `谁在说？`
2. `他把什么算作成功？`
3. `什么根本没有被算进去？`

正式正文只保留一句世界内评价，不把这三个问题写给玩家。说话者必须真心认为流程正常、结果合理；不能主动承认自己邪恶，也不能由作者补一句“这很荒谬”“这是一场灾难”替玩家解释。

### 9.2 荒诞可以发生在不同地方

| 发生在哪里 | 具体写法 |
|---|---|
| 检查范围 | 只检查设备是否修好，不检查材料从哪里来 |
| 统计口径 | 把失败者移出名单，于是合格率自然提高 |
| 名称和标准 | 把缺陷改名为功能，或把同一种误差写进统一标准 |
| 价格与采购 | 报价足够低以后，质量问题失去继续讨论的预算 |
| 新技术与旧手续 | 能力已经改变，申请、审批和领用办法仍按旧世界运行 |
| 部门交接 | 每个部门都完成了自己的工作，合起来却得到荒唐结果 |
| 宏大目标的第一用途 | 文明级能力首先被拿去解决奖章、报表或争夺收益这类小事 |
| 人被记成资产或耗材 | 制度只计算岗位、财产、产量或可替换部件，没有把人的处境算进去 |

这些只是可选位置，不要求每条都写地狱笑话，也不要求反转永远放在句尾。它可以藏在科技名称、验收范围、操作提示、缺失的统计项或各部门的正常反应里。

### 9.3 去重与直接退稿

- 一条正文只选一个主要荒诞来源，不同时堆入改名、审计、省钱、伤亡和委员会鼓掌。

- 增加伤亡人数、把普通人换成士兵、把工人换成科学家，都不算新的反转。
- `至于……他们是谁`、`全体起立鼓掌`、`不是吗`等落句不能被当成固定模板反复套用。

## 10. 第六项提案：强度看真实后果，不看句子用了多少狠话

第 10.1 至 10.6 节保留第六项第一次提案的完整讨论过程。用户在 `M0-S003-U057` 只接受其中的中度与重度判断，并明确要求笑话从中度起步；轻度分类、旧的四档配比以及固定`“……”——某机构`示意均已由第 10.7 节起修正，不能继续作为当前方案。

### 10.1 四级的实际差别

| 强度 | 玩家读到的实际情况 | 判断办法 |
|---|---|---|
| 完全严肃 | 不设置笑点，认真写技术成就、历史变化、探索欲或文明态度 | 去掉机构名后，仍是一句真诚的技术或历史评价 |
| 轻度 | 表格、旧手续、面子工程或宏大能力的小用途有点荒唐，但没人因此失去生计、基本权利或安全 | 即使保证所有人安全，笑点仍然成立 |
| 中度 | 有人真实失去工作、财产、尊严、选择权、生活条件或安全余量，但死亡和永久身体伤害不是制度运行的必要材料 | 制度知道有人承担代价，仍认为结果合格 |
| 重度 | 人的身体、自由、死亡、失踪、强制改造或群体毁灭，被直接当成工具、耗材、测试办法或成功条件 | 把不可逆伤害拿掉，这套制度就无法按原方式运行 |

武器巨大、死亡数字多，不会自动变成重度。正常介绍灭星武器的能力可以完全严肃；只强迫一个人失去身体控制，也可以是重度。

### 10.2 上一项示例为什么不够

- `未通过测试的机床没有编号`和`标准件仍填写旧序列号`只属于轻度：前者是统计机灵，后者只是办事麻烦，没有形成真实代价。
- 已接受的`把工人的经验从工人身上剥离出来`属于中度：它写到职业、地位和经验所有权被拿走，但不靠死亡成立。
- 重度不能靠把同一句里的死亡人数改大。它必须写清身体、自由或死亡怎样被制度直接拿来完成目标。

### 10.12 已确认的因果质量门

本轮确认的核心不是一种固定句式，而是一条写作顺序：

> 先把因果跑通，再把因果藏起来。藏起来不等于没有逻辑。

每条中度或重度评价在动笔前都必须能写出完整暗线：

```text
科技效果 → 必然产生的结果 → 某个旁人为什么必须处理这个结果
```

正文只露出这条暗线末端的一个侧面，不替玩家解释中间步骤。验收时逐条回答：

1. 这项科技具体改变了什么？
2. 这个改变为什么必然影响当前人物、岗位或场所？
3. 这个人为什么一定会遇到正文中的东西，而不是作者为了段子把他拉来？
4. 换成另一项科技后原句是否仍然成立？若成立，科技绑定不够。
5. 正文是在留下足够线索，还是在删掉必要逻辑后假装含蓄？

任何一问答不上来，直接重写；不得靠更惨的名词、更短的句子或更用力的笑点掩盖断裂因果。

### 10.13 一个侧面不等于一句话

- 它可以是一句话、两三句、小对话或一段很短的事件；长度只服从因果是否够清楚。
- 角色把荒诞后果当作正常业务处理，不代替作者解释制度多么黑暗。

### 12.5 第八项第四部分：`5:4:1` 按独立阅读计数

判断句为：玩家第一次会把它当作几篇完整内容阅读，就算几条；同一正文只是展开、悬停或换位置重复展示，仍算一条。

| 玩家实际读到的内容 | 计数 |
|---|---|
| 一张科技卡中的技术说明与世界内评价 | 一条；按整块正文最终呈现的严肃、中度或重度归类 |
| 科技卡展开、悬停或回看时重复同一完整正文 | 仍是一条 |
| 有独立标题和完整正文的探索、档案或考古发现记录 | 另算一条，并按自身强度归类 |
| 只有`来源：旧时代档案`一类提示或回看入口 | 不增加计数 |
| 同一已接受模板代入其他设施名称或数字 | 不增加计数 |
| 重复建设、普通进度、事故日志、日常运行文字和按钮提示 | 不参与 `5:4:1` |

例如，玩家先读到一篇完整的旧时代数据中心发现记录，之后又读到《人格热备份》的科技正文，这就是两条。发现记录严肃、科技正文中度，就分别记一条严肃和一条中度；不能合成一条中度，也不能把重度评价藏进发现记录后只统计科技卡。

`5:4:1` 继续是长线比例，不要求机械地每十条正好五、四、一；重度最多 10%，没有自然成立的重度内容时回到完全严肃。该边界沿用 `D-M0-PROD-044`。

### 13.1 最终结论

1. 科研卡默认只让玩家快速比较名称、效果、短说明和图标；成本与领域由图标说明，完整正文从名称或短说明展开。只接受信息层级，不接受当前示意的视觉样式。
2. 科技正文使用两个内容段落：第一段写技术能做什么或改变了什么，第二段写世界内部人物或机构的评价。效果栏继续单独写玩法结果；两行《恢复精密制造》是已接受校准成品。

4. 当前情况回原页面，发生过的事实进日志，值得注意的状态变化只通知一次。普通进度、自动推进和日常维护不打扰玩家，事故修好后自然结束，不出现挑战通过弹窗。
5. 黑色幽默必须由科技效果造成真实后果，再从必须处理该后果的侧面露出；说话者真心认为制度正常，一条只使用一个主要荒诞来源。换机构名、通用受害叙事和无因果段子直接退稿。
6. 长线比例为完全严肃 50%、中度 40%、重度最多 10%；不机械凑数，重度不连续，没有自然重度时回到严肃。来源决定历史归属，当前实施决定现在的责任。
7. 文案描述世界，数据解释系统。科技来源在首次发现记录建立；首座工程节点一至两句，重复完成一句，事故只按发生、处理、变化和结束记录事实。
8. 一条内容从第一层到第四层始终使用一张内部工作单；缺什么就停在负责层。AI 检查全部，用户逐条确认高风险成品并抽查普通重复内容；`5:4:1`按玩家独立阅读计数。最终下层任务采用独立 Codex 线程，由当前逻辑主线程统筹。
