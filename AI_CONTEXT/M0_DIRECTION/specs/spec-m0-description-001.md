# SPEC-M0-DESCRIPTION-001 · M0 工程与科技描述结构、风格与总规格冻结

## 1. 本规格决定什么

本规格只决定工程、科研、设备、阶段报告、维修和制度类文字怎样组织。科研候选卡先服务快速比较，完整正文再解释技术与世界内情况；需求、时间、阻断和实时状态放在真正负责这些信息的项目页或状态页，不能把所有底层字段挤进一张科研卡。

本任务不写具体负责人的完整故事，不写最终科技正文，不修改已经接受的机制、数字和结果，也不修改游戏代码。只有本规格逐项被用户接受，并最终整体接受后，才可以把 `overall_spec_frozen` 标为 true。

## 2. 已接受输入与不能改动的事实

- 科研完成只解锁图纸、方法、工程或制造条件，不直接生成设施、设备、产量、库存或地图情报。
- 实体能力必须经过制造或修复、运输、部署、标定、配人、供能和维护中实际需要的环节，才对指定阶段生效。
- 第一座前哨首次阶段报告固定说明新事实、工程影响、当前缺口、预计时间、完成结果和下一步；没有真实选择时不暂停工程。
- 第二座复制与重复建设的普通进展进入短日志；只有新事实、真实选择、阻断和验收完成才主动提示。
- 工程页面显示基础方案时间、当前方案时间和缩短原因；科技页面只能显示部署后的预计影响，不能把预计效果伪装成已经生效。
- 所有人员、物资、工作量、地点、设备状态、暂停原因和恢复条件都引用已接受的真实状态，不新增“文案专用”变量或效果。
- 来源附件只提供通用规则：技术本身可信，荒诞主要来自制度怎样解释结果；不复制或仿写小说原文、章节与专有名词。

## 5. 第一项修订依据：两个真实科研写法

### 5.5 第一项验收边界

第一项只接受“玩家先看到什么、悬停后看到什么”的信息结构，不接受当前示意的长相。卡片形状、布局、尺寸比例、颜色、字体、图标风格、间距、边框、悬停框和整个科研页面构图都必须在整体 UI 方向确定后重新设计；第四层不得照着当前示意实现。

范例中的“恢复精密制造”、科研工作量 24、工程制造分类及正文只用于检查信息层级，也不因第一项 accepted 而成为最终文案、分类或数值。整卡点击、触屏和手柄交互同样留到整体 UI 与输入方案中统一决定。

## 6. 第二项返工：先确认什么才叫正文

### 6.1 第一版为什么撤回

用户在 `M0-S003-U045` 指出，第一版“恢复精密制造”仍然是在解释研究解锁什么、还缺什么和系统怎样运行，不是一篇玩家会阅读的科技正文。尤其是“研究完成后只解锁……”一段属于玩法说明，应由已接受的效果行、工程页与状态页承担，不能冒充世界内文字。

用户又在 `M0-S003-U046` 指出，第一篇纯世界内候选仍有两个问题：技术段太长；“灾难中已完成”不够像真正的制度地狱笑话。自我认知完全正常的机构不会主动把自己的处境或做法命名为灾难，它只会按正常科目、验收口径和责任划分继续工作。

因此第一版三项共同底线和类型表暂不接受，也不能交给第二层、第三层当正文模板。第二项先退回到一篇成品文字，确认正文身份后再从成品反推最低标准。

### 6.2 当前正文边界

- 正文只写世界内部存在的设备、工艺、试验、使用和制度后果，不出现“玩家、本科技、解锁、效果、前置条件、工程页面”等系统外语言。
- 世界内参数可以出现，例如公差、温度、连续运转时间和报废件数；`+5%`、科研工作量、内部等级和状态字段不能混入正文。
- 卡片效果负责告诉玩家研究后得到什么；项目页负责显示物资、人员、地点、时间和阻断；正文不重复这两层说明。
- 删除制度性结尾后，前面的技术过程仍必须可信；制度荒诞来自验收、统计、程序或成本怎样解释结果，而不是技术本身故意失效。

### 6.3 修订后的正文候选

```text
恢复精密制造

工程组将用封存量块校准量具，重新测定导轨、丝杠和主轴的误差，再以泵轴、阀芯与轴承座连续试切。三批试件的尺寸误差都在二十微米以内，旧机床即可恢复精密加工。

七十二小时耐久测试将与首批正式生产合并进行。试产期间的伤亡计入人力损耗，不计入设备故障；只要三批零件合格，项目仍按零故障通过验收。
```

技术段现在只保留两句；结尾中的机构没有承认异常，也没有向玩家解释笑点。它只是把伤亡放进人力科目，把设备验收继续记为零故障。当前继续等待用户判断正文语气、长度和地狱笑话强度；确认正文身份后，再讨论第二项最低标准。第一项保持 accepted，第三至第八项保持 pending，整套 M0 仍未冻结。
