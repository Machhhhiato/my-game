# 事件、灾害、事故、战争结果与跨系统恢复闭环

## 1. 第一规则：事件只改变真实对象

事件不是科技、奖励包、日期章节或弹窗文本。完整生命周期为：

```text
真实状态达到候选条件
→ 发现并建立事件对象
→ 证据可信度与影响范围逐步确认
→ 玩家选择已有能力能够执行的响应
→ 生成任务、资源占用、权限与时间范围
→ 人员、产品、设施、路线、环境和关系发生真实变化
→ 评估损害、恢复、责任和长期后果
→ 形成科研、工程、法令或组织改进候选
```

没有真实来源时不生成事件；没有真实能力时不能显示虚假解决按钮；事件不能凭空增减库存、人口、关系或科技。

## 5. 法令、政策与状态

法令5项：紧急状态权限期限、灾害预警疏散、救援人员与物资征用补偿、事故报告独立调查、战时平民保护与失踪伤亡登记。政策5项：区域紧急响应、临时疏散安置、关键服务恢复、污染隔离清理、战后复员重建，均限定地域、期限、资源和复核。

状态8项：风险可见、预警可达、指挥任务可追溯、专业救援可用、伤亡失踪可核对、关键服务可恢复、损害责任可调查、复盘能够转化为真实改进。

## 6. 统一结算与战争反馈

事件本身不使用独立货币。响应任务消耗现有人员、车辆、燃料、装备、医疗、住房和预算；损害直接修改对应资产状态、库存、人口、环境和关系。恢复使用普通工程、维修、医疗、物流和财政逻辑。

战斗结果继续记录命令位置时间线、型号装备故障、弹药燃料、伤亡救治失联、战术进退、补给维修、缴获和战后评审。玩家只从实战、演习、缴获和可靠情报看到型号表现，不显示全知敌我数值比较。

第2年至少能完成一次跨部门事件从发现、响应、损害、恢复到复盘的闭环，并能把战争伤亡、装备损失、占领、外交、人口和工业后果写回各自系统。本轮不填事件概率、固定日期、损害倍率、战斗公式和恢复天数。

旧类型修正：事件族不是科技，事件文本不是状态，损失不是抽象惩罚，恢复不是一次按钮，战后报告不能自动升级装备；所有结果都必须回写真实对象。
