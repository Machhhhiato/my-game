# 两年恢复期完整科技树制作合同

## 1. 第一规则：实际展示只包含单个具体科技

- 实际科技树的唯一展示单位是**可以单独研究的具体科技**。每个可见节点必须有自己的稳定 ID、完整科技名称、直接科技前置、研究结果、明确解锁和完整正文。
- `方向`、`主干`、`阶段`、`产业链概括`、`第 730 日能力`、`终点产品目录`、`事件族`、`实体部队结果`以及任何总览性说明，都只是讨论、组织、审计或验收时使用的内部总结，**不得出现在实际科技树或思维导图的展示结果中**。
- 总结不得占据节点、连接线、详情页、完成记录或科研队列位置，不得被研究、解锁或作为其他科技的前置；也不得用一项总结替代其中应当逐项存在的具体科技。
- 实际展示中的每一条连接只能连接两个具体科技，表示真实科技前置或科技间的明确交叉依赖。产品、设施、部队、事件与终点能力只作为具体科技的结果或实体条件写入详情，不画成科技节点。
- 方向和总结可以在内部数据中帮助制作、校验和排版，但任何最终实际展示文件都不得显示这些总结。任何产物只要仍把总结画成节点、面板或可展开内容，就自动退回，不能进入验收。

## 2. 本轮交付目标

从离开避难所开始，到具备可持续恢复基础 21 世纪生产力的能力终点，逐项完成全部方向，最后只以一棵完整科技树交用户验收。

制作期间不再要求用户逐方向确认。所有方向先维持 `review_candidate`，只有最终完整科技树得到用户接受后，相关候选才整体转为 accepted。

最终交付必须同时包含：

1. 全部可单独研究的具体科技与稳定节点 ID；方向归属只作内部校验，不进入展示；
2. 每项科技的完整名称；
3. 下级科技、工业、人口、设施和运行证明；
4. 科研实际形成的知识、标准、设计或组织能力；
5. 明确解锁的工程、设施、产品、型号、制度或部队；
6. 生产、检验、维护、补给与复制要求；
7. 玩家可见的直接效果短行；
8. 已讨论的完整科技正文与署名/评价行；
9. 型号、代际、库存、换线和改型关系；
10. 科技到科技的跨方向依赖；第 730 日倒推只作内部验证；
11. 一份只由具体科技及其真实依赖构成的思维导图，不显示方向、主干或能力总结。

## 3. 时间规则

- 开局第 1 日和第 730 日只用于讨论跨度、工作量和科研难度。
- 任何节点只检查实际前置，不检查日期是否到达。
- 研究、试制、建设、训练、运输和统合仍消耗真实工作时间。
- 提前取得档案、设备、贸易知识、缴获样品或外部专家，可以减少研究工作，但不能跳过本地适配、生产、检验、运行和维护证明。

## 4. 统一科技节点合同

每个正式科技节点必须提供：

| 字段 | 必填内容 |
|---|---|
| 稳定 ID | 不随玩家名称和显示布局改变 |
| 所属方向 | 仅供内部制作与审计的 33 方向标签，不进入实际展示 |
| 完整科技名称 | 不使用`科技二级`、`工业二`等占位名 |
| 节点类型 | 发现、方法、设计、标准、组织、试制、定型或运行证明 |
| 直接科技前置 | 必须先掌握的下级节点 |
| 实体前置 | 人员、设施、材料、能源、路线、样品或组织 |
| 研究工作量 | 必填基础研发点、难度档位和真实工作构成；按月结算，不形成日期门 |
| 科研结果 | 知识、图纸、标准、流程、训练大纲或组织能力 |
| 明确解锁 | 工程、设施、产品、型号、制度、合同或部队 |
| 实体生成条件 | 建造、生产、检验、登记、训练或采用条件 |
| 维护与失效 | 如何维持，缺少什么会降级或停用 |
| 直接效果短行 | 玩家能立刻理解研究开放了什么 |
| 完整正文 | 说明技术怎样改变产业、社会和普通生活 |
| 评价/署名行 | 形成世界内立场，不重复效果说明 |

科研完成不能直接生成建筑、库存、人口、贸易收入、军队或抽象全局加成。

## 5. 节点类型与依赖方向

```text
发现与测绘
  ↓
原理与方法
  ↓
实验、样品与小范围试验
  ↓
设计、标准与组织方法
  ↓
工程或试制开放
  ↓
建设、生产、登记、训练或协议执行
  ↓
检验与运行证明
  ↓
跨地点复制、改型或下一代科技
```

不是每个产品都必须机械复制八个节点。只有确实产生不同玩家决定、风险或里程碑时才拆分；纯工序细节留在实体前置和运行证明中。

## 6. 科研难度

科研难度由以下内容共同形成：

- 未掌握原理的比例；
- 需要整理和校验的遗产档案；
- 样品、测量和试验次数；
- 所需专业人员和训练；
- 依赖设施、能源和材料的稀缺程度；
- 安全、伦理和公共验证要求；
- 从单件成功到可复制运行之间的差距。

每个节点必须依据 `SPEC-M1-MONTHLY-RESOURCE-RESEARCH-SETTLEMENT-001` 使用`简单 / 常规 / 进阶 / 复杂 / 重大 / 突破`六档，填写 5—640 范围内的基础研发点，并另列实际工作组成。1 个标准科研人月产生 10 个基础科研点；项目进度只在月结增加，预计时间以剩余月结次数表达，不对应固定日期。投入更多合格人员、设施和样品可以提前完成，但不得跳过硬前置。

## 7. 产品与型号合同

```text
产品家族
  → 技术代际
    → 正式型号
      → 生产批次
        → 库存与部署
          → 维护、改型、再制造或回收
```

- 产品家族只在用途发生明显变化时分开。
- 技术代际只在玩家能感受到性能、用途、可靠性、维护或生产方式跨越时升级。
- 每代正式投产产品必须有拟真型号或代号，并与完整产品类型并列。
- 直接数值比较不作为爽点；改进通过真实生产、运输、故障、维护和战斗结果体现。
- 同型号修订保留最多生产熟练度，同代新型号次之，跨代换线损失更大，无关产品换线损失最大。
- 具体比例留待完整纸面账本校准。

## 8. 科技正文合同

每个正式节点最终使用三层玩家文字：

1. **完整科技名称**；
2. **直接效果短行**：只说研究开放的具体对象；
3. **完整正文**：第一段说明技术、产业、设施和生活改变，第二行用世界内机构、从业者或社会观点作评价。

正文不得：

- 把任务说明、内部 ID、等级、字段或百分比写给玩家；
- 声称尚未生产、建设、采用或运行的实体已经存在；
- 用空泛的`效率提高`代替具体变化；
- 凭空补写人物、机构、地点、性能、伤亡或历史；
- 把研究完成写成全社会自动采用。

## 10. 完整性门禁

最终树必须通过：

- 实际展示节点全部是可单独研究的具体科技；方向、主干、阶段、终点能力、产品目录、事件族和实体部队结果均未进入展示；
- 每个节点的稳定 ID 唯一；
- 每条前置引用存在且无循环依赖；
- 每个上层节点至少有一个下层能力或实体证明；
- 每个产品能追到材料、能源、工具、设施、检验和维护；
- 每项外交、收入、人口和军队结果能追到实际实体；
- 每个第 730 日能力都能从开局条件向前走通；
- 不要求玩家等到某个日期才继续；
- 所有正文与对象事实一致；
- 思维导图与文字科技树使用同一组节点和依赖。
