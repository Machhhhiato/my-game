# 单项科技与独立产物合同

## 1. 第一规则：科技与产物都必须是独立对象

实际科技节点只能是一项能够学习、验证、复制和继续改进的具体原理、方法、工艺、设计或标准。一个科技可以开放多个结果，但每个产品、设施、工程、行动、记录、组织、编制、训练、协议或有限期政策都必须拥有独立对象，不得把多个结果合写成一个“体系”“能力”“产品族”或“综合工程”。

## 2. 科技身份门

以下对象可以成为科技：

- 可复现实验或测量方法；
- 可复现制造、施工、检验或维修工艺；
- 具有明确输入、原理和验证方法的设备或产品设计；
- 能由训练和演习验证的具体编制、战术或指挥方法；
- 能被第二团队按相同规则采用的具体技术标准。

以下对象不能成为科技：

- 河流、矿藏、旧管线、人口、聚居点等自然物或世界实体；
- “调查某地”“修复某厂”“组建某部队”等一次性任务；
- 把若干不同对象放在一起处理的联合工作包；
- 产品、设施、工程、记录、组织、部队或政策本身；
- 只表示发展阶段、方向、体系成熟度或第若干代的总结名称。

名称中出现多个并列对象或多种物理过程时必须逐项复核。只有它们共同构成不可分割的同一原理、同一工艺循环或同一可验证战术动作时才可保留为一个科技；不能因为开发方便而聚合。

## 3. 产物对象类型

| 类型 | 定义 | 产生方式 |
|---|---|---|
| 产品 | 可制造、入库、运输、消耗、维护或配发的物品 | 生产线制造并检验入库 |
| 设施 | 可持续运行并占用地点、岗位和维护的实体资产 | 工程建成或旧设施修复验收 |
| 工程 | 有具体地点、投入、阶段和验收的一次性实体项目 | 玩家批准后施工 |
| 行动 | 在具体对象或地点上重复执行的勘察、检测、训练、外交或军事任务 | 派出人员与装备执行 |
| 记录 | 由真实行动形成、可复核并继续更新的地图、档案、清单、报告或标准文件 | 行动或运行结果写入 |
| 组织 | 有岗位、人员、装备、职责和运行状态的常设组织 | 招募、任命、装备和采用 |
| 编制 | 用于组建实体部队或团队的岗位与装备模板 | 科研形成，实际单位另行组建 |
| 训练 | 部队或岗位可以实际执行并留下合格记录的课程 | 教官、场地、装备和人员训练 |
| 协议 | 与真实外部主体签订、具有权利义务和履行状态的协议 | 谈判并由双方接受 |
| 有限期政策选项 | 在真实缺口、风险或冲突存在时可由玩家颁布的行政行动 | 玩家决定生效范围和期限 |

`记录`不是库存产品，`工程`不是科技节点，`政策选项`不是科研完成后自动生效的法令，`编制`也不等于实体部队已经组建。

## 4. 解锁关系

每项科技必须分别记录：

1. 直接科技前置；
2. 研究形成的具体知识或设计；
3. 独立开放的每一个产物对象；
4. 各产物所需的实体条件；
5. 产物如何实际生成；
6. 后续可以作为哪些科技、工程或行动的前置。

科技完成只能开放产物的制造、建设、执行、组建、谈判或颁布资格，不自动生成任何实体结果。

## 5. 水务五项校准样例

### 地表径流测量与季节流量评估

- 独立行动：地表水源流量测定。
- 独立记录：地表水源连续流量记录。
- 独立设施：简易水文测站。
- 独立工程：地表取水口建设。
- 独立工程：原水输送线路建设。
- 条件政策选项：枯水期取水限制。

### 地下水水文地质勘探

- 独立行动：地下水候选区勘探。
- 独立记录：含水层候选分布图。
- 独立记录：候选井位报告。
- 独立工程：勘探钻孔施工。

### 浅井钻探、护壁与成井

本名称仍包含三个不可自动视为同一科技的施工环节，R3 拆为：

- 浅井钻进工艺；
- 井壁护壁与井管安装；
- 滤水结构与洗井成井。

对应独立产物包括：勘探浅井工程、生产水井工程、井台卫生防护工程、标准井管、滤水管组件和井用泵组。每项产品和工程分别登记。

### 埋地管线定位与管网测绘

R3 拆为：

- 埋地管线定位方法；
- 旧管网连接关系测绘标准。

对应独立产物包括：旧管线探测行动、探坑确认工程、管段位置记录、阀门位置记录和旧管网连接图。

### 旧供水系统分段试压与漏损诊断

R3 拆为：

- 管网分段隔离与压力试验；
- 压降分析与漏损定位。

对应独立产物包括：管网分段试压行动、管段承压记录、漏点清单、漏点抢修工程、阀门更换工程、临时旁路供水工程和管段更换工程。

只有实际出现枯水、污染或检修停水时，相关科技和事实才共同开放`枯水期取水限制`、`水源保护区临时管制`或`管网检修期间分区供水`等有限期政策选项；科研不会自动颁布它们。

## 6. R3 验收

- 没有任何科技名称只是方向总结或联合任务；
- 没有任何产物名称同时代表多个可独立建造、生产、执行或颁布的对象；
- 每个显示对象具有唯一类型和稳定内部 ID；
- 科技到科技、科技到产物、工程到设施、行动到记录分别使用不同关系；
- 同一科技开放多个产物时逐项显示，不使用“等”“相关设施”“综合能力”或未展开的“产品族”；
- 日期继续只用于难度与周期讨论，不构成解锁门槛。

## 7. 第2年终点实体补充合同

### 7.1 工厂与设施

- `工厂类别`是战略工业容量分类，不是科技、产品或单个建筑。第2年工厂类别以 `SPEC-M1-FACTORY-CLASS-PRODUCTION-LINE-001` 为准。
- `厂址实例`是真实生产设施：占用地点、设备、能源、公用设施和岗位，并保存损坏、维护和可安装生产线数量。
- `生产线`是生产分配的最小单位；每条生产线只增加一个玩家可管理产品 ID，各自结算输入、岗位、产量、熟练度、检验、停机和换线。该产品可以是通过尺度审查的标准化供应组。
- 同一厂址可以安装多条相容生产线，但厂址和工厂类别都不拥有“混合产量”；库存只落到具体产品和型号。
- 一项科技可以同时开放多个产品或多条生产线资格，但必须逐项生成玩家值得管理的对象。螺栓、螺母、螺钉和垫圈合成`基础紧固件`；内部规格留在配方和质量记录中。只有同工厂类别、同主要工艺、同主要用途、同短缺后果且没有独立调度价值的细项才允许如此聚合。
- 不同工业类别、危险许可、短缺后果、代际里程碑、储运维护方式或可独立停产后果的对象必须分开。`通用产品`等跨用途万能集合名仍不得入库。
- 空包装、食品原料和罐藏食品分别是产品。食品生产线消耗包装与食品，只产出一种明确食品，不能同时把包装登记成自己的产品。
- 军营、仓库、试验场、矿场、发电站和维修中心是其他设施，不进入制造工厂容量。维修、大修和再制造恢复原产品状态，不生成抽象维修产品。
- 一条科技开放的`产品`、`工艺`或`工程`不能自动证明厂址或生产线存在；必须由工程建成或旧设施修复验收，并具备人员、能源、原料、维护与检验后才能生产。

### 7.2 法令、政策与记录

- `法令`是长期生效、面向全部适用对象的权利义务规则；科技只能开放颁布资格，法令由玩家或具有授权的中央机关另行颁布。
- `有限期政策选项`只处理具体缺口、风险或冲突，必须保存生效范围、期限、执行机关、资源代价和结束条件。
- `记录`只保存执行事实。配给登记、批次记录、预算账和服务接入计划都不是法令或政策本身。
- 当前 R4 中标作有限期政策的`批次配给记录`与`配给关系登记`按本合同重新判定为政策执行记录；真正的政策对象由 `SPEC-M1-YEAR-TWO-END-STATE-001` 单独定义。

### 7.3 服务与状态

- 水、电、热、医疗、教育、通信和运输等连续服务不是可入库产品；它们由设施和组织按月产生服务流量，并由真实服务对象消耗。
- `状态`不是科技产物类型。状态只能由人口、实体、库存、服务和运行证据派生，不能通过研究、建设按钮或记录文件直接设置为成立。
- 终点状态下降或失效不删除已经完成的科技；它只表示当前实体和运行证据不再满足状态合同。

### 7.4 汇总边界

工厂目录、设施目录、法令目录和终点状态可以在方向规格与验收页面中归纳多个原子结果，但不得回写成总结科技，不得作为实际科技树节点，也不得取代底层产品、工程、设施、行动和记录对象。
