# SPEC-M0-PROGRESSION-001 · M0 科研、高级资产与前哨复制

## 1. 本规格要决定什么

本规格把关键科研、普通科研自动推进、精密制造中心、勘测无人机、第一座工业废墟回收前哨和第二座自动复制连成一条真实能力链。

本规格不制作完整科技树、其他前哨类型、能源系统、战争、舰队或不可解释的自动 AI，也不授权修改游戏代码。

## 2. 已确认边界

- 玩家可以集中人力和物资突破一个关键目标，普通科研允许按领域倾向自动推进；两者都必须使用真实科研人力，不生成免费科研点。
- 科研只在白昼推进。2/4/6 人仍是科研最低、标准、加速档；P0 至 P3、安全线、物资预留、暂停和恢复沿用 `SPEC-M0-OPS-001`。
- 科技完成只解锁设计、工程或制造能力，不能直接生成设施、资产、产量或地图情报。
- 开局没有精密制造中心、勘测无人机、远程前哨和废墟回收标准工程包。
- 精密制造中心不能要求精密部件作为自身建造前置；首批工程构件和合金料来自已确认的有限旧设备库、总部拆解区与现场材料。
- 勘测无人机必须进入已经接受的方向线索、范围确认、路线确认、现场确认流程，不能一键揭示地点全部资料。
- M0 没有通用电网，也不增加能源或燃料库存。无人机自带电源不能顺带解锁夜班、卡车、叉车或连续生产。
- 第一座工业废墟回收前哨由玩家完整主导；第二座同类前哨在玩家批准地点、优先级与投入上限后自动复制，但仍消耗真实人力、物资、白昼和运输。
- 标准工程包是图纸、工序、适用范围和验收经验，不是库存，也不是抽象速度加成。

来源：`D-M0-PROD-003`、`D-M0-PROD-005` 至 `D-M0-PROD-007`、`D-M0-PROD-016`、`D-M0-PROD-018` 至 `D-M0-PROD-020`、`D-M0-PROD-023`、`SPEC-M0-PLAY-001`、`SPEC-M0-OPS-001`、`SPEC-M0-MAP-001`。

## 4. 第一项接受版本：一条真实科研工作线，两种选题方式

### 4.1 M0 只有一处基础科研工作区

总部开局有一处使用旧资料、旧仪器和手工工具的基础科研工作区。它能研究，但不能制造精密部件，也不代表总部已有能源。

M0 同一时间只推进一个科研项目。科研使用真实的 2/4/6 人档，只在白昼产生项目进度；少于 2 人时暂停。进度保存在具体项目上，不形成可以存储、转移或一次灌入别处的“科研点”。

未来如果建成第二处真实科研设施并投入另一批人员，可以再讨论并行科研；M0 不凭界面上的第二个队列免费产生第二份科研能力。

删除“发展人力池”这个说法。没有可执行科研时，已分配的科研人员仍留在基础科研工作区待命，不产生科研进度；玩家可以把他们调到其他具体岗位。

### 4.2 第一种：指定目标或手动排队

玩家可以在科研树上点击任意已经显示的远期科技。系统沿依赖关系向前展开，把尚未完成的必要前置和最终目标放入一条完整可见的队列：

- 已经完成的前置直接划去；
- 已经有部分进度的项目保留进度；
- 多个目标共用的前置只排一次；
- 互不依赖的项目可以由玩家换序；
- 有依赖关系的项目不能移到其前置之前，界面直接说明原因；
- 互斥分支、重大路线和不可逆选择停在选择点，不能由系统代选；
- 设施、资产或现场条件只显示为实际阻塞，不能被伪装成科研步骤自动完成。

玩家也可以不点远期目标，直接逐项添加和预排科研项目。无论由目标展开还是手动排列，玩家看到的都是同一条指定队列。

### 4.3 第二种：按领域顺序自动推进

M0 先只显示当前确实存在普通项目的三个领域：

- 制造与材料；
- 勘测与地图；
- 工程与后勤。

玩家把参与自动科研的领域排成严格顺序：

| 设置 | 自动科研怎样处理 |
|---|---|
| 第一、第二、第三 | 按界面从上到下的顺序进入下一阶段和补普通科技 |
| 不参与自动 | 不进入自动轮次；玩家仍可在该领域手动指定目标 |

不使用并列优先，也不再使用“优先、正常、维持、暂停”四档。玩家直接拖动领域顺序，系统没有隐藏的同级判断。未来农业、能源或防务真正拥有项目后再显示对应领域，不在 M0 放空分类。

### 4.4 “下一阶段”由明确科技判断

所有领域共用可比较的阶段编号 `0、1、2……`，但每个领域可以显示自己的阶段名称。每个领域都在科研树上标出对应编号的阶段入口科技；完成这个入口科技，才算该领域进入对应阶段。

- 阶段不按完成科技数量、百分比或隐藏评分判断；
- 进入下一阶段只前进一级，不会把第一领域自动研究到科技树末端；
- 阶段入口所需的确定前置可以自动加入；
- 可选普通科技不影响阶段判定；
- 互斥前置和不可逆路线仍等待玩家选择。

某个领域达到当前内容的最高阶段时，显示“已到当前上限”，不再参与更高阶段的轮次；以后解锁新阶段后再自动加入。每个普通科技也必须标明所属阶段，避免手动提前突破后遗漏旧阶段的普通科技。

阶段的具体名称、入口科技和项目工作量交 `M0-L1-105` 纸面演算；本项先冻结阶段必须由公开节点判断。

### 4.5 自动轮次：先突破，再追平，最后补普通科技

系统查看所有参与自动科研且仍有更高阶段的领域，以其中最低阶段的下一个阶段作为本轮共同目标：

1. 只处理尚未达到本轮目标的领域，并按第一、第二、第三的顺序完成确定前置和阶段入口；
2. 所有参与领域达到本轮目标后，再从第一领域开始，补完所属阶段不高于本轮目标且允许自动研究的普通科技；
3. 同一领域有多个普通科技时，按领域内公开顺序执行；玩家可以调整互不依赖项目的先后，也可以标记“不自动研究”；
4. 每完成一个项目就重新检查一次全部前置；只有完整扫描后再无可执行项目，才报告本轮阻塞；
5. 本轮所有可自动研究内容完成后，再计算下一轮目标。

如果某个领域已经被玩家手动推进到更高阶段，自动轮次先跳过它，让其他领域追上；所有参与领域追平后，它才再次第一个进入新阶段。这样第一领域总是先获得新阶段能力，但不会在其他领域完全不动时连续领先很多阶段。玩家如果要集中冲击更远的关键科技，使用第一种指定目标方式。

普通科技只包括已经公开、没有互斥选择、没有被玩家标记为“不自动研究”的项目。如果被排除的项目后来成为阶段必要前置，系统直接显示冲突，不会绕过。

某个参与领域被路线选择、跨领域前置或实际条件阻塞时，系统显示原因，并先完成其他领域不超过本轮目标的可执行内容；随后重新扫描。仍不能让全部参与领域达到本轮目标时，不得开始更高阶段。玩家解除条件或把该领域改为不参与自动后，系统才重新计算本轮。

### 4.6 两种选题方式怎样接续

- 指定目标和手动队列排在领域自动队列之前，但不会与自动队列同时运行；
- 玩家加入指定目标时，可以选择立即切换，或完成当前自动项目后切换；已有项目进度不清空；
- 指定队列清空后，如果领域自动开启，就保留原来的本轮目标和执行位置，但按当前科技树重新生成并去重尚未完成的内容，不能恢复已经过时的旧队列；
- 指定路线因自身条件受阻时，默认停住并说明原因；玩家可以手动调整队列，或开启“受阻时临时自动”。临时自动不会取消指定目标；条件恢复后，完成当前自动科技就回到指定目标；
- 玩家调整领域顺序时，当前科技默认做完，尚未开始的内容立即按新顺序重排；玩家也可以选择立即切换。加入或移出自动领域会重新计算本轮目标，但已有完成和项目进度全部保留；
- 整条科研工作线因安全线和全局 P0 至 P3 规则暂停时，两种选题方式都停止，不能靠切换领域绕过；
- 领域第一、第二、第三只决定研究什么；科研工作线的 P0 至 P3、物资供应和 2/4/6 人分别决定能否推进和推进速度。

界面显示当前项目来自“指定队列”还是“领域自动”、完整队列、当前自动轮次、领域阶段、实际投入人数、预留物资、剩余工作以及每次自动选择原因。

### 4.7 M0 的实际例子

三个领域都处于阶段 0，玩家排列为制造与材料第一、勘测与地图第二、工程与后勤第三。自动顺序为：

`制造 0→1 → 勘测 0→1 → 工程 0→1 → 按制造、勘测、工程的顺序补阶段 1 普通科技 → 制造 1→2……`

玩家随后点击远期科技“恢复精密制造”。系统把确定的必要前置和目标放到指定队列前方；领域自动停在原轮次。目标完成只解锁精密制造中心建设条件，不会直接生成制造中心或精密部件；指定队列清空后，领域自动从原位置继续。

具体阶段名称、科技节点、工作量、所需白昼和试验物资交 `M0-L1-105` 纸面演算；本项只冻结控制方式、队列展开、自动轮次和玩家接管边界。

本项由用户在 `M0-S003-U029` 接受，形成 `D-M0-PROD-030`。

## 5. 第二项提案：精密制造中心与勘测无人机实体链

### 5.1 完整能力链

第二项按以下实体顺序运行：

`恢复精密制造研究 → 建造精密制造中心 → 安装与校准 → 试制和检查 → 批量生产精密部件 → 制造勘测无人机系统 → 补能与部署 → 编入勘测计划 → 返航判读、检修与再次补能`

科研完成、中心建成、精密部件入库、无人机制造完成和地图获得新情报是五个不同节点，任何一步都不能代替后面的实体工作。

### 5.2 精密制造中心怎样建成

“恢复精密制造”完成后，只解锁总部内一个已清理设施位上的建造项目。项目使用已经接受的工程 3/6/9 人档，只在白昼推进，并消耗工程构件、合金料、普通零件和真实工程时间。

建造中心不消耗精密部件，也不要求无人机、废墟情报或第一座前哨作为前置，避免主链自我锁死。

建造过程为：

`场地准备 → 安装手动或脚踏精密机具 → 安装测量与校准台 → 校准 → 试制 → 检查`

建造材料只负责把设施建成，不能顺便变成产品。开始试制前，必须另外预留一批合金料和普通零件，并投入实际工程人员与白昼。试运行不是随机成功判定；设施完好、试制人员和材料满足时，完成全部工序就通过。通过后中心变为“可生产”，完成检查的合格试制批才进入精密部件库存。

M0 的中心是利用旧夹具、光学测量工具和人力机具工作的低速精密工坊。它能在无电网阶段白昼运行，但不能提供动力生产、夜班或连续制造；这些升级必须等待真实能源设施。

### 5.3 中心只有一条精密任务队列

中心同一时间只做一项精密工作：

- 批量生产精密部件；
- 组装和校准一套勘测无人机系统；
- 维修无人机的传感器、控制器或电源包等高级损坏。

精密部件按实体批次生产：开始时预留合金料和普通零件，投入 3/6/9 人与白昼加工，完成检查后才把成品加入库存，不按每天增加抽象产量。

中心进入现有维护体系。日常维护主要使用普通零件和维护工时；维护不足先降低实际速度并预警，再暂停。

中心停机后的最低恢复是中心之外的工程项目，使用工程人员、普通零件、工程构件和白昼，不占用已经失效的中心任务位，也不要求精密部件。修复完成后必须重新校准，才能恢复部件生产、无人机组装和高级维修。

### 5.4 勘测无人机是一套可分配资产

M0 先制造一套多光谱勘测无人机系统，并把它作为一个资产管理，避免逐架微操。制造使用中心的精密任务位、工程 3/6/9 人档和白昼，并消耗：

- 工程构件：机体、运输箱和地面设备；
- 合金料：耐用结构和运动部件；
- 精密部件：传感器、控制器、通信和携带电源；
- 普通零件：连接件和日常可维护部件。

完成后得到无人机本体、多光谱传感器、可拆携带电源包、专用人力充电台和运输维护箱。同一套资产有真实地点、状态和任务归属，不能同时服务两个勘测方向。

无人机至少保存：`制造中、可用且已充电、已分配、执行任务、返航待检查、待补能、补能中、待维修、严重损坏、完全损失`。

### 5.5 无通用电网时怎样补能

无人机使用可拆携带电源包和随设备制造的脚踏或手摇专用充电台：

- 电量属于无人机资产状态，不增加第七种库存；
- 一次完整出动消耗一个可用电源周期，具体架次和补能白昼交 `M0-L1-105`；
- 返航检查与补能都是维护与手工作坊队列中的真实任务，只在白昼推进，占用实际维护人员和工时，并服从任务 P 级、安全线与维护积压；
- 玩家在勘测计划中预先允许，只代表这些任务可以自动排队，不代表免费完成或抢占 P0 关键维护。没有可用工时就停在“返航待检查”或“待补能”；实际安排人员后才进入“补能中”；
- 充电台没有输电网络、照明线路或通用动力接口，不能给中心、灯光、卡车、叉车或其他设施供能；
- 以后建成真实能源设施，才可以替代人力补能并提升周转；M0 不实现这次升级。

### 5.6 无人机怎样进入既有勘测

玩家仍按 `SPEC-M0-MAP-001` 一次批准勘测方向、2/4/6 人、P1 至 P3 和投入上限，并增加“允许调用无人机”设置。批准前同时显示预计占用的勘测人员和维护工时。

飞行、数据接收和判读使用勘测 2/4/6 人；返航检查与补能使用维护人员；高级维修、重新组装和校准使用工程人员与中心任务位。三个阶段不能把同一个人同时计算多次，也不会因为整条计划已经批准就复制人员。

第一次扫描只需要玩家批准方向，无人机沿该方向和已经知道安全的空域工作；出现候选格与候选连接后，玩家再批准一条候选路线供后续扫描。出现多条路线时系统不能暗选。无人机不能从完全未知的全球地图中自动找到所有地点，也不能因为尚无路线确认而无法执行第一次任务。

一次批准后，系统可在范围内自动完成准备、出动、返航和判读，并把检查与补能提交到对应真实队列；当前白昼不足以安全返航时不启动新出动。

| 正在推进的情报阶段 | 无人机实际帮助 | 不能替代 |
|---|---|---|
| 方向线索 | 扫描批准方向的远处地表，把候选地点缩小到范围确认 | 不直接给出精确资源、道路、危险和最终地点 |
| 范围确认 | 补充地面、水况、废墟轮廓和明显障碍，排除明显错误区域 | 不证明道路承重、泥层深度或废墟内部情况 |
| 路线确认 | 查看道路表面连续性、河流、泥地、桥涵外观和明显阻断，把地面检查缩小到少数疑点 | 不检查路基承重、桥涵下部、车辆实际通行和地下危险 |
| 现场确认 | 标出积水、温度、污染和金属异常，指出可进入位置、明显坍塌区和优先检查区 | 不进入内部或地下，不取样、清理、测试结构、确认可回收批数或形成最终选址结论 |

无人机唯一可以独立改变的情报状态是`方向线索 → 范围确认`。此后只能减少路线确认和现场确认的剩余工作，不能单独把状态推进到路线确认或现场确认。具体减少多少工作量交 `M0-L1-105`。

### 5.7 维护、损坏和防软锁

- 返航检查是每次出动后的正常步骤，普通状态只消耗时间，不随机吞掉精密部件；
- 普通损坏按`普通零件与维护工时 → 返航检查 → 补能 → 可用`恢复；
- 传感器、控制器或电源包严重损坏按`精密部件、工程人员、白昼与中心任务位 → 修复 → 校准测试 → 补能 → 可用`恢复；中心任务位不能替代实际人员和时间；
- 充电台机械损坏可以用普通零件和维护工时恢复，避免无人机完好却永久无法补能；
- 完全损失后必须重新制造，不能自动恢复；但损失必须来自已经显示的故障、风险批准或长期维护不足，M0 必达主线不会用无预警隐藏随机数摧毁唯一资产；
- 无人机不可用时，玩家可以等待修复或把计划改为纯人工。人工勘测始终能完成四级情报，只是更慢；
- 已经获得的地图事实、勘测阶段和剩余工作不会因无人机损坏、换回人工或重载而清空；
- 制造中心状态、在制批次、物资使用、无人机地点、电源、维护、任务与勘测情报全部进入存档。

主链物资锁定必须同时覆盖中心建设、单独的试制批、首套无人机和第一座前哨最低需要，不能被可选项目提前消耗。无人机完全损失且自由物资不足时，已经接受的总部拆解区缓慢恢复来源仍可积累重建材料；这不会立刻返还无人机，但保证存在真实恢复路径。

具体建造物资、每批产量、制造白昼、补能时间、出动次数、工作量减免和维修成本交 `M0-L1-105`；本项只冻结实体依赖、资产状态、勘测作用和恢复口。
