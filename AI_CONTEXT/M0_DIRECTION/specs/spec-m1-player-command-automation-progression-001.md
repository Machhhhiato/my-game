# 玩家命令、自动规则与内容推进

## 1. 第一规则

```text
时间只推进当前世界状态，不负责把游戏推进到预定内容阶段。
```

世界日始终向前走。新的科技、工程、生产线、扩建、兼并、贸易安排、部队组建和制度变化，只有满足以下任一条件才会开始：

1. 玩家明确下达命令；
2. 玩家预先建立的自动规则明确授权系统开始；
3. 已经下达的命令本身包含可连续执行的队列或重复条件。

没有命令，也没有自动规则时，游戏可以无限推进世界日，但不会为了配合五分钟、两小时或任何阶段目标，自动选择新科技、开新工程、切换产品或扩大势力。

## 2. 时间继续发生什么

“内容不自动推进”不等于冻结世界：

- 已经开始的科研继续获得实际科研点，直到完成、暂停或失去条件；
- 已经开工的工程继续消耗材料、人力、设备和运输，直到完成、暂停或受阻；
- 已经投产的生产线继续生产当前产品，直到达到玩家设定的库存目标、输入中断、故障、停产命令或换产命令；
- 已有居民继续消耗、工作、出生、衰老、患病和死亡；
- 库存继续损耗，设备继续磨损，维护、服务、贸易合同和军队补给继续结算；
- 已存在且符合规则的外部事件可以发生，危机也可能让当前状态恶化。

如果当前循环可持续，世界会维持或缓慢积累；如果当前循环不可持续，世界会衰退。时间本身不会替玩家解决问题，也不会凭空制造发展。

## 3. 每类对象的停止点

| 对象 | 已有命令如何继续 | 命令完成后的默认状态 |
|---|---|---|
| 科研 | 当前科技持续获得科研交付 | 科技完成并停下，等待下一项；不自动选科技 |
| 工程 | 当前项目持续施工 | 项目验收并退出队列；工程队等待新命令 |
| 生产 | 当前产品按已设数量或库存目标重复生产 | 达到停止条件后待机；不自行换产 |
| 维护 | 按已设优先级处理当前维护队列 | 队列清空后保持待命，可按规则接收新故障 |
| 贸易 | 履行现有合同和路线 | 合同到期后停止；不自行签署新合同 |
| 外交 | 执行已授权接触、谈判或统合任务 | 当前任务结束后等待决定 |
| 军事 | 执行当前编制、训练、驻防或行动命令 | 命令完成后保持当前姿态，不自行发动新行动 |
| 治理 | 现行政策、法律和法令继续按自身规则运行 | 不自行改变政策；临时法令按退出条件终止 |

## 4. 自动规则是什么

自动不是系统替玩家玩，而是玩家提前写下可重复执行的命令。每条自动规则必须包含：

- 适用对象或范围；
- 触发条件；
- 可使用的人员、预算、库存或设施上限；
- 执行优先级；
- 停止条件；
- 遇到冲突时是等待、降级还是提交玩家决定；
- 最近一次执行的原因和结果。

可接受的自动规则示例包括：

- 研究队列完成后按玩家已经排列的顺序研究下一项；
- 某类备件低于三个月覆盖时，把现有生产线切回该备件；
- 已批准厂区内的标准扩建，在材料与工程队空闲时自动排队；
- 关键设备故障时按维护优先级调拨备件；
- 已签订合同按库存上限和运输能力重复履行。

自动规则不得替玩家决定新的领土扩张、首次外交立场、人口权利、不可逆选址、主动战争或唯一战略资源归属。

## 5. 玩家实际在玩什么

玩家的核心操作不是点击时间节点，而是：

1. 选择下一步能力目标；
2. 下达科研、工程、生产、贸易、治理和军事命令；
3. 把愿意重复的操作固化为自动规则；
4. 观察资源、地图和社会结果；
5. 处理自动规则无法裁决的冲突、危机和新机会；
6. 修改目标、队列、阈值和优先级，让同一套世界系统产生新的发展路径。

因此，挂机来自玩家建立了一台能够自行运行的国家机器，而不是系统按照预设时间表播放发展动画。

## 6. 科研—工程—生产示例

在没有自动规则时：

1. 玩家选择一项科技并开始研究；
2. 科技完成后，研究设施待机；工程只显示为可启动，不自动开工；
3. 玩家选择工程、地点和投入后，工程持续施工；
4. 工程验收后，工程队待机；设施存在，但没有生产命令时不生产；
5. 玩家设置产品、批量或库存目标并分配人员后，生产线开始重复生产；
6. 达到库存目标后，生产线待机。

在玩家设置自动规则后，同一链条可以自动衔接，但每一步都必须能追溯到玩家已经设置的队列、计划、库存阈值或优先级，而不是追溯到经过了多少现实分钟。

## 7. 两小时口径

- 前五分钟形成千人小循环、标准路线约两小时达到基础二十一世纪生产力，继续作为平衡与体验目标。
- 该目标假设玩家持续下达关键命令，并逐步建立合理自动规则。
- 玩家不操作且没有自动规则时，终局可以永远不发生。
- 玩家建立更好的自动化、路线和资源配置时，可以更早完成；错误配置、战争、短缺和长期待机可以无限延后。
- 时间段只能用来检查“一个正常游玩样本是否太快或太慢”，不得驱动内容生成或解锁。

## 8. 界面要求

- 顶栏时间只显示世界正在运行，不显示“下一阶段将在多少分钟后到达”。
- 每个科研、工程和生产对象必须分别显示当前命令、是否允许自动接续、停止条件和当前限制器。
- 队列空闲时明确显示“等待命令”或“没有符合自动规则的任务”，而不是虚构一项系统推荐任务正在推进。
- 自动规则必须由玩家可见、可关闭、可修改，并保存最近执行记录。
- 时间加速、离线补算和挂机返回只批量执行已有命令与自动规则，不补发本来没有下达的内容。

## 9. 当前边界

本规格的第一规则与“命令或明确自动规则才推进新内容”已经由用户确认。第10至13节的统一命令与自动规则只保留为底层执行模型；V5因预制确认被退回，V6因暴露微观调度被退回。当前以第22至23节的战略控制尺度与V7候选为准；它尚不是正式产品实现授权。

`M1-L4-523`的交互设计门禁已经由用户接受解除，当前为`ready_waiting_dispatch`。正式派发以前仍不得修改产品代码，也不得把退回的V4时间轴内容作为实现来源。

## 10. 统一命令模型

科研、工程、生产、维护、贸易和军事不再各自发明一套自动化。所有可执行对象统一使用四种操作身份：

| 身份 | 含义 | 完成后 |
|---|---|---|
| 手动单次命令 | 玩家现在要求执行一次明确动作 | 对象回到待命 |
| 明确队列 | 玩家已经排列多个具体动作 | 只按队列顺序继续，队列空后待命 |
| 条件规则 | 玩家批准在条件成立时重复执行一种动作 | 条件不成立时等待，成立时执行 |
| 常设状态 | 政策、法律、维护底线、驻防姿态等持续约束 | 直到玩家修改或自身退出条件成立 |

系统不得把“建议”“里程碑”“标准路线”或“AI认为合理”冒充上述任何一种身份。

## 11. 自动规则统一判定

```text
规则可执行
= 已启用
× 触发条件成立
× 目标已经获得玩家批准
× 人员与设施容量可用
× 资源与路线允许
× 未超过预算和库存上限
× 没有更高优先级冲突
```

规则每次执行都必须记录：规则名称、触发事实、实际动作、使用资源、被谁阻塞、停止原因和结果。没有这些字段的“自动”不得存在。

当多条规则争夺同一资源时，默认裁决顺序为：

1. 已确认的紧急响应；
2. 玩家设定的最低生存和关键服务底线；
3. 防止关键资产失效的维护；
4. 玩家钉住的单次命令；
5. 玩家排列的队列；
6. 条件规则的显式优先级；
7. 其余对象待机。

该顺序本身可在后续治理与预算系统中细化，但不得静默跨越玩家已经设定的底线。

## 12. 各系统的最小自动化

### 12.1 科研

- 玩家选择当前科技；可选地把若干已知科技排入明确队列。
- 当前科技完成后，只有队列中存在下一项时才继续。
- 领域优先、自动选择“最便宜科技”或自动追逐终局目标不作为默认能力；若以后提供，必须是玩家明确建立的高层研究计划。

### 12.2 工程

- 玩家选择要执行的工程或设施升级，并排列先后顺序。
- 当前项目完成后，只有工程序列中存在下一项时才继续。
- 工程队、施工设备、材料、运输、具体选址和施工方法由系统结算，不形成玩家控件。
- 自动规则不得自行扩张厂区、新增工程或改变玩家排列的顺序。

### 12.3 生产

玩家只选择产品或设备，并为其分配工厂数量。生产持续执行，直到玩家停止、改产、减少工厂，或者系统因底层条件不足进入等待。

人员、原料、能源、班次、产线细节、效率、合格率、库存流转与维护由系统结算。产线不得因为科技完成、库存变化或系统建议自行换产，也不得弹出微观调度要求。

### 12.4 维护

- 故障登记、安全停机、备件调拨、维修队派遣和日常维修按设施规则自动发生；这属于保持现状，不属于发展内容。
- 玩家只决定设施是否升级、是否执行大修工程，以及政策或法令规定的战略优先类别。
- 底层维护冲突形成瓶颈或停机结果，不要求玩家逐件分配备件或维修人员。

### 12.5 人力与公共服务

- 玩家通过建设或升级公共设施、选择政策和设定法律标准改变公共服务规模。
- 岗位、人员、资格、轮班和自动补员由系统根据设施与制度结算，不形成逐岗操作。
- 系统不能以自动补员为由创建未经玩家建设的机构，也不能改变政策与权利身份。

### 12.6 贸易、外交与军事

- 已签合同可按数量、库存和期限重复履行；系统不自行签订新合同。
- 已授权接触或谈判可以继续，但首次立场、兼并和权利条件必须由玩家决定。
- 训练、补给、维修和驻防可按常设规则循环；主动战争、越境行动和新战略目标不得自动开始。

## 13. 空闲与阻塞必须分开

每个对象只允许显示以下一种主要状态：

- `执行命令`：正在消耗实际投入推进；
- `等待条件`：已有命令或规则，但某项可验证条件尚未成立；
- `阻塞`：条件本应成立但出现需要处理的缺口；
- `等待命令`：没有任何命令、队列或适用自动规则；
- `目标保持`：当前循环正在维持玩家设定的库存、服务或姿态；
- `完成待命`：单次命令已经结束，对象没有下一项授权。

“等待命令”不是错误，也不应触发红色警报。只有它造成玩家设定的底线即将失效时，才升级为需要处理的缺口。

## 14. V5界面候选（已退回）

`always-game-command-automation-v5.html`只保留底层状态机证据，不再作为当前交互候选。它曾验证：

- 世界日期在没有任何命令时持续推进，科研、工程和生产保持原状；
- 玩家可以先批准工程计划、先设置未来库存目标，再决定是否启用自动接续；
- 玩家单独下达科研命令后，科技完成，研究设施待机，工程不会自行开工；
- 启用“条件满足后自动开工”后，系统只启动已经批准的工程计划，并显示执行来源；
- 工程验收后，设施存在但没有库存目标时不生产；
- 玩家可以设置20台库存目标，选择手动生产、验收后自动执行一次，或低于目标时自动补产；
- 库存被实际使用后，没有补产规则则保持较低库存，有规则才重新启动当前产品；
- 地图始终保留，并用同一工业场址显示待命、计划、在建和运行状态。

用户接受了“无命令不推进内容、自动规则只执行玩家授权”的底层，但退回了以下交互：系统预先选定工业场址和工程内容，玩家只点“批准计划”；系统预先写死20台生产目标，玩家只点“设为20台”。这仍然是系统替玩家做好选择。

## 15. V5裁决

以下内容继续保留：

1. 时间只结算现状；
2. 单次命令、明确队列、条件规则和常设状态四种授权身份；
3. 空闲、等待条件、阻塞、执行和目标保持的状态区分；
4. 自动规则只能重复玩家已经配置好的行为。

以下内容被退回：

1. 由系统替玩家选择工程地点、规模和投入后，只留下“批准”按钮；
2. 由系统替玩家写死产量或库存目标后，只留下“确认”按钮；
3. 把预制的单一路线包装成自动化配置。

## 16. 玩家构成方案，不审批系统方案

```text
系统提供对象、约束和后果；玩家组成方案并下达命令。
```

玩家的有效操作必须改变至少一项实际配置，而不是只接受系统给出的完整答案：

| 系统 | 玩家必须能够选择或分配的内容 | 系统负责计算的内容 |
|---|---|---|
| 科研 | 研究哪项科技、科研先后顺序、是否执行或暂停序列 | 研究人员、设施、样品、科研点交付、缺口与完成判断 |
| 工程 | 哪项工程或设施升级是否执行、先做哪项、后做哪项 | 工程队、施工设备、材料、运输、地点细节、施工阶段与建成结果 |
| 生产 | 生产什么产品或设备、投入多少座工厂、何时停止 | 工人、原料、能源、班次、产线、效率、合格率、库存、磨损与维护 |
| 维护 | 哪类资产处于战略优先、是否启动大修或设施升级 | 维修队、备件、工序、停机安排、维修结果和消耗 |
| 贸易 | 交换对象、数量、价格或义务、路线、期限和库存底线 | 对方条件、运输能力、履约结果和外部风险 |
| 军事 | 部队类型、编制、装备分配、训练、补给和任务 | 战备、损耗、补给压力、维修与战斗结果 |

系统可以显示预测、主要限制器和可能后果，但不得默认替玩家选好战略方案，也不得把底层调度转嫁给玩家。工程队、工人、施工设备、材料、运输路线、班次、生产输入优先级、合格率和维护细节都只属于模拟层。第一次打开一个未配置对象时，应显示未选择、零工厂或实际继承值；不能用系统推荐值悄悄形成命令。

## 17. 生产命令的玩家配置

生产界面只要求玩家明确完成以下配置：

1. 选择产品和可用型号；
2. 从可用工业能力中分配工厂数量；
3. 下达或停止生产命令。

工人、原料、能源、班次、产线细节、生产方式、库存流转、维护和合格率均由系统自动结算。它们可以作为结果和瓶颈展示，但不形成逐项操作控件。

统一生产关系为：

```text
实际月产
= 分配工厂或产线
× 单位产能
× 人员满足率
× 输入满足率
× 能源满足率
× 当前效率
× 合格率
```

玩家决定生产哪种设备、投入多少工厂，系统计算能生产多少以及能否持续；系统不得反过来给出固定产量让玩家确认，也不得要求玩家逐项配工人、材料和能源。

## 18. 工程命令的玩家配置

工程和设施升级只保留三项玩家动作：

1. 从已解锁工程中选择一个实际项目；
2. 决定是否执行，并排列工程与升级的先后顺序；
3. 对升级项目选择要升级的既有工厂或设施。

工程队、施工设备、材料、运输、具体落点、施工方法和阶段推进由系统决定。项目若因底层条件不足而不能执行，只显示等待原因；玩家通过调整工程序列、建设新的战略能力或修改政策解决，不直接调度底层对象。

## 19. 自动化的来源边界

自动规则只能保存和重复玩家已经下达的战略指令，例如：

- 持续生产玩家指定产品，并保持玩家分配的工厂数量；
- 当前工程完成后，执行玩家已经排好的下一项工程或升级；
- 当前科技完成后，研究玩家已经排列的下一项；
- 已签合同在玩家设定的库存底线以上重复履约。

规则允许系统在条件成立时执行，不允许系统替玩家补齐缺失的科技、工程、产品、工厂数量或战略目标。

## 20. 当前下一步

V6已经退回。它取消了预制确认题，却把工程队、施工设备、材料优先级、生产人员、输入优先级和库存区间等底层数据交给玩家，仍不符合战略层控制尺度。当前候选改为V7：玩家只决定科研与工程序列、生产设备与工厂数量、设施升级、政策、法律和法令。

## 22. 战略控制尺度

玩家是中央政府的战略决策者，不是工程经理、车间主任或基层调度员。可见操作固定为：

1. 选择科技并排列科研顺序；
2. 决定工程或设施升级是否执行，并排列先后；
3. 选择生产的设备或产品，并投入多少座工厂；
4. 选择政策倾向与法律标准；
5. 发布、取消或等待临时法令到期。

底层模拟仍完整存在，但只通过“预计结果、主要瓶颈、等待原因和完成结果”反馈。不得为工程队、工人、施工设备、材料、能源、运输、班次、生产线细节或维护工序设置玩家控件。

## 23. V7战略控制候选

文件：`always-game-strategic-control-v7.html`。

- 科研只选择项目和队列顺序；系统结算研究人员、设施和样品。
- 点击科技卡片立即加入科研序列，不再使用“选中科技—加入队列”的二次确认。
- 科研队列中的项目右键立即移出；移出当前研究会放弃当前进度，并从玩家排列的下一项继续。
- 工程与升级只选择项目、目标和队列顺序；系统结算施工资源与落地细节。
- 生产产品固定显示为独立生产行；每行直接显示并增减投入工厂数量，不再先选择产品再设置统一数量。
- 工厂数量调整立即改变该产品的生产分配；系统结算人员、原料、能源、效率与维护。
- 政策、法律与临时法令保留为中央政府直接控制的战略制度。
- 无指令时只推进当前世界状态，不生成下一阶段。
- 1024、736和360像素浏览器验收通过，无横向溢出；完整证据见`M1_STRATEGIC_CONTROL_SCOPE_VISUAL_AUDIT_001.md`。

当前状态：`accepted_baseline`。用户已明确接受战略控制范围、科技点击即入队、队列右键移出和固定产品行工厂分配。该交互门禁已经解除；产品实现仍须由第一层另行登记并派发第四层任务。
