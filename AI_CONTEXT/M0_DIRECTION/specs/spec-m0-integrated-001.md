# SPEC-M0-INTEGRATED-001 · M0 前 90 日纸面试玩与机制整合验收

## 1. 本规格决定什么

本规格把已经接受的开局、资源、人力、地图、科研、资产和前哨规则放到同一张前 90 日账本里，逐项填入可演算数值，检查玩家在 30–45 分钟内能否完成一次完整流程。

本任务只在以下三件事都成立时进入整体验收：

1. 第 1–90 日的库存、人员、工单、运输和科研能够连续结算；
2. 5–8 次关键操作确实改变进度，三条最低内容线不是后台占位；
3. 集中发展、稳定发展和第 90 日尚未完成三种走法都不会因规则矛盾而卡死。

本任务不写剧情、正式玩家文字或游戏代码，也不再承担整套 M0 的最终冻结。`M0-L1-105` accepted 后进入 `M0-L1-106`；只有 `M0-L1-106` accepted 且用户明确标记 `overall_spec_frozen` 后，才进入第四层只读审计。来源：`D-M0-DIR-007`。

## 4. 第一项：T00 时间换算与纸面账本格式

### 4.1 首轮提案

| 项目 | 首轮提案 | 说明 |
|---|---|---|
| 纸面试玩参考速度 | 1 个游戏日约等于 20 秒现实时间 | 纸面验收固定使用这一速度；实际游戏可以换速，但不能用临时加速证明时长达标 |
| 90 日纯推进时间 | 约 30 分钟 | 第 1 日至第 90 日共完成 90 次日结算，`90 × 20 秒 = 1800 秒` |
| 必读报告与 5–8 次必要操作 | 合计约 5–10 分钟 | 无论阅读和操作时是否暂停，都计入 30–45 分钟目标 |
| 一局预计总时长 | 约 35–40 分钟 | 位于已接受的 30–45 分钟目标内 |
| 不计入目标时长 | 必要阅读和操作之外的额外思考、主动离开、挂机与离线时间 | 这些玩家自行延长的时间不能反向拉长或缩短工单 |

底层结算统一使用游戏日、白昼和工作量。实际游戏速度只改变界面上的现实分钟换算，不改变科研、运输或工程所需工作量；纸面验收始终使用固定参考速度。玩家读必读报告和完成必要操作时若暂停，账本仍把这段时间记入“阅读/操作”，同时不让资源和工程暗中推进。

### 4.2 每条账本记录必须有的字段

| 字段 | 用途 |
|---|---|
| 游戏日与白昼 | 确认事情在第几日发生，夜间是否停工 |
| 现实推进时间 | 按固定纸面参考速度换算的累计推进时间 |
| 阅读/操作时间 | 必读报告、比较方案和必要下令所用的现实时间；额外暂停另列且不计目标 |
| 人口与岗位 | 基本值守、四条日常线、发展、外派、远程运输和无法工作的实际人数 |
| 六种库存与占用 | 期初、流入、消耗、期末，以及主链锁定、项目预留和可自由使用量 |
| 底线与预测 | 水、食物、普通零件的硬底线、玩家安全线、覆盖日数和未来趋势 |
| 项目供应顺序 | P0–P3、同级队列顺序和当前实际领到的人力与物资 |
| 活动工单 | 当前阶段、投入、工作量、已完成、剩余、阻断与预计完成日 |
| 暂停与恢复 | 暂停原因、恢复条件、人员去向和是否已授权自动恢复 |
| 设施状态 | 健康、维护积压、当前产能、故障和可用接口 |
| 科研控制 | 指定目标或领域自动模式、当前项目、前置队列、自动选择原因和剩余工作 |
| 运输与装卸 | 批次货物、路线段、剩余路程、两端装卸状态及人员设备位置 |
| 前哨与工程包 | 七段工单、试产/验收/有效回运批次、工程包版本和地点适用判断 |
| 实体位置 | 人员、设备、货物和运输批次当前所在格或设施；同一实体不能重复占用 |
| 玩家动作与直接后果 | 玩家改变了什么，哪些数值或预计完成日因此变化 |
| 自动结果 | 没有新命令时系统依据哪些已批准规则继续运行 |

第一项只确认换算口径和记录格式，不在此时确认后续资源、工时或产量数值。

## 5. 待填写的三张基础表

### T01 · 第 1 日状态

第二项开始时先原样载入以下已接受基线，不能重新当作待定方案：

| 已接受基线 | 内容 |
|---|---|
| 28 人标准分配 | 基本值守 7、供水 4、食物 5、维护与手工作坊 3、总部短途物流 3、发展人力 6 |
| 日常线最低/标准/加速 | 供水 2/4/6；食物 3/5/7；维护 2/3/5；总部短途物流 2/3/5 |
| 项目线最低/标准/加速 | 科研 2/4/6；勘测 2/4/6；工程 3/6/9；远程物流 2/3/5 |
| 开局水窗口 | 约 10 日是停止补充时的开局覆盖时间和水务修复窗口，不是玩家安全线 |
| 硬底线/默认安全线 | 水 2/5 日；食物 3/7 日；普通零件 3/5 日标准维护量 |
| 资源与供应规则 | 六种可见库存；P0–P3；同级可见队列；主链锁定、项目预留、暂停与逐项恢复 |

第二项只继续填写尚未接受的绝对库存量、每日流入与消耗、设施健康、维护积压和地图当前事实；不得用一个“初始资源包”概括。

### T02 · 日常流入、消耗与维护工作

逐日保存供水、食物和普通零件的来源、人员、流入、消耗、底线与暂停后果，同时列出科研、精密制造、勘测、工程和物流会从同一批人力与库存中拿走什么。已接受的人数档位与 P0–P3 直接作为表头约束，本项只填流量、工作量、成本和产量。

### T03 · 主链工单

逐项保存科研前置、精密工坊修复、无人机制造与自动返航补能、四段勘测、七段首建和第二座复制的人员、物资、设备、工作量、前置、并行条件和恢复路径。第二座对应首建“工艺适配”的阶段必须写成“工程包现场核对”，不能重复占用科研线。试产批次、验收回运和验收后才计入观察的有效回运分别记账。阶段稳定验收由系统按已接受事实自动完成，不新增玩家验收按钮。

## 6. 必须完成的纸面运行

| 运行 | 玩家倾向 | 要证明什么 |
|---|---|---|
| A · 集中发展 | 守住或在预警后恢复安全线，短期集中人员、物资和高优先级 | 走到第二座自动稳定、两次有效自动回运、第一座继续运行、一个普通自动科研完成、三种生命保障守住或恢复安全线，并完成一次保存退出重载 |
| B · 稳定发展 | 保持较高储备和日常投入，科研按领域自动推进 | 以较少操作走到与 A 相同的完整观察终点，系统不偷取底线资源 |
| C · 第 90 日未完成边界演算 | 至少一条主链晚于目标日 | 系统列出缺项、原因和恢复动作，跨过第 90 日后仍能继续并最终恢复，不突然判负 |

随机事故不塞进三条正常时间线当固定考点。另用固定随机种子或明确标记为 `TEST_ONLY` 的触发，验证事故的发生、影响、修复、损失保留和续局。

## 7. 暂定的 7 次关键操作位置

以下只是后续填表用的占位顺序，不在第一项接受时冻结：

1. 设置水务人员、优先级和安全线；
2. 在科研树指定精密制造的远期目标，必要前置自动展开或由玩家预排序推进；
3. 批准精密工坊修复并预留主链物资；
4. 批准无人机制造和第一次勘测；返航、检查接入与被动补能按资产规则自动循环；
5. 比较两处废墟后批准第一座七段首建；
6. 玩家主动做一次管理优化，在清理、科研、工程和物流之间调整并行投入；这不是阶段弹窗、必点确认或完成首建的前置；
7. 第一座自动稳定并形成工程包后，批准第二座真实复制。

第一座稳定验收由系统完成，不把“点一下验收”虚构成关键操作。

## 8. 两道验收门与 L105 交付检查

- 链路测试门：时间、账本、资源与科研投入、精密制造、勘测、第一座首建、工程包、第二座复制、物流回运和观察首尾相接；保存、退出、重载后能够从同一状态继续运行。
- 正式内容门：供水、食物、维护/零件和废墟探索都来自真实地点、人员、流入、消耗、反馈与恢复；玩家完整经历第一座首建，第二座减少重复操作但仍付出真实人力、物资、时间和运输；终点、观察、存档、第 90 日未达成与真正失败规则都成立；5–8 次操作确实改变时间、资源或风险；30–45 分钟体验没有必需内容断层。

两道门分别记录证据。链路跑通不能代替正式内容完整，也不能代替用户对体验的判断。

`M0-L1-105` 另有一份交付检查清单：集中和稳定两次完整纸面运行、第 90 日未完成边界演算、状态存档检查和单独事故测试都有可追溯记录，开放的机制问题已经清零。这是任务交付检查，不是第三道产品验收门。
