# M1 十万人规模精简系统、产品与原子对象架构

## 1. 精简的含义

本轮精简只允许四种动作：

1. 把多个玩家导航页收进一个核心系统；
2. 删除没有独立玩法价值的常设机构层级；
3. 把误标为科技的值班规程、登记动作、验收记录和日常业务恢复为组织操作；
4. 把没有独立库存、调度和短缺决策的中间状态或内部部件移回配方、批次状态或物料清单。

精简绝不允许：

- 用一个“综合科技”替代多个不同原理、不同验证或不同产物的科技；
- 用一个“综合产品”吞掉需要不同工厂、库存、储运或用途的产品；
- 用一项“综合工程”同时代表可以分别建设、损坏、停用和维护的设施；
- 用一项“综合法令”同时约束税收、警察用权、证据、羁押、采购和申诉；
- 因为多个对象放在同一页面、园区或行政体系中，就让它们共享一个 ID。

一句话规则：**系统可以合并，职能可以最小化，对象不能含糊化。**

## 2. 原子身份继续写死

进入科技树、生产、建设或立法数据的对象必须满足：

- 一项科技只研究一种可复现能力，拥有唯一`technology_id`；
- 一个产品只有一个明确库存身份，拥有唯一`product_id`；
- 一项工程只建设或实质改造一个可独立验收的实体，拥有唯一`project_id`；
- 一项法令只规定一组不可再拆的长期权利义务，拥有唯一`law_id`；
- 一项科技可以解锁多项结果，但科技、产品、工程、法令、组织、行动和记录必须分别列成多项关系；
- 名称中出现“与”“及”“综合”“一体化”时必须重新检查：若两部分可以分别研究、生产、建设、颁布、停用或短缺，就必须拆开；
- 被精简掉的对象只能明确改成操作、记录、状态、配方、内部部件或后期路线，不能被偷偷塞进另一个对象名称。

### 2.1 食品与空罐仍是硬例子

以下对象继续完全分开：

```text
空金属食品罐生产科技
  → 空金属食品罐产品
  → 空罐生产线

食品杀菌与罐藏科技
  → 罐藏食品生产资格
  → 罐藏食品生产线

空金属食品罐 + 明确食品原料
  → 罐藏主食 / 罐藏蛋白食品 / 罐藏蔬菜
```

食品系统可以把三条链放在同一导航页，但罐厂、食品厂、空罐和三种罐藏食品不得合并。

## 3. 十个玩家核心系统

原先用于完整性检查的18个系统组收成10个玩家系统。系统只负责导航、预算和状态汇总，不成为科技树节点。

| 核心系统 | 玩家处理的核心问题 | 吸收的旧讨论范围 | 不得合并的原子对象示例 |
|---|---|---|---|
| 人口与聚居点 | 人口、住房、土地、公共工程、消防和基本生活承载 | 人口、人力、住房、公共工程、消防、生活水平 | 住房工程、道路工程、消防站、市场设施分别建设 |
| 农业与食品 | 土地、种源、农业投入、收获、食品加工和储备 | 农业、畜牧、食品、储备 | 谷物、面粉、空罐、罐藏食品分别生产 |
| 资源与公共网络 | 采矿、林业、能源、水务、通信、环卫和环境承载 | 资源、能源、水务、通信、环境 | 电力、水、通信是不同地点化服务；矿场、发电站、净水厂分别建设 |
| 工业与建设 | 材料、工厂、机械、质量、维护、再制造和工程施工 | 冶金、化工、工厂、机床、质量、维修、建造 | 炼钢厂、化工厂、机械厂、维修中心分别存在；产品仍逐项入库 |
| 运输与贸易 | 道路、车辆、仓储、跨地库存、市场和外贸 | 道路、车辆、物流、市场、合同、关税、贸易 | 道路工程、车辆产品、仓库、贸易合同分别存在 |
| 科研与教育 | 科研组织、实际研究、学校、职业教育、学徒和岗位资格 | 科研、教育、培训、资格 | 科研项目、学校工程、资格记录分别存在 |
| 医疗与照护 | 基层医疗、急救、住院、公共卫生、康复和长期照护 | 医疗、公共卫生、妇幼、康复、社会照护 | 医院、急救站、照护设施和医疗产品分别存在 |
| 政府与法律 | 税收预算、行政服务、警察、法律与最低司法 | 财政、税收、行政、警务、司法接口、审计 | 税法、警察用权法、证据法、羁押法分别颁布；行政厅、警务站、司法设施分别建设 |
| 军事与国防 | 征募、训练、装备生产、编制、部署和持续保障 | 军事科技、产品、部队、战斗结果 | 枪械、弹药、车辆、通信、医疗装备和部队实体分别存在 |
| 外交与领土统合 | 接触、协议、贸易关系、停火、兼并和地方接入 | 外交、兼并、地方治理、合法性 | 外交协议、主权移交、地方接入工程和申诉案件分别存在 |

事件、灾害、事故和战争恢复不再作为第11个常设系统。它们是作用于上述十个系统真实对象的跨系统事件层，只保留事件对象、损害、任务和恢复关系。

## 4. 政府与法律只保留四个核心逻辑

### 4.1 税收与预算

玩家只决定：向谁、按什么基础征收；公共支出投向哪里；是否减免或紧急追加；是否接受审计纠正。

保留的实际能力：

1. 统一账户与月末核对；
2. 税费义务核算与征收；
3. 部门预算与追加修订；
4. 公共采购、合同与验收；
5. 地方收入、中央转移与用途约束；
6. 独立审计与纠正。

价格历史、应收应付、抵扣、外部估值、票据和盘点仍可作为业务记录，但不分别占用科技树节点。

### 4.2 行政

玩家只决定：人口与居留怎样登记；地方服务由谁办理；新并入地区何时接入中央制度；行政积压优先清理什么。

保留的实际能力：

1. 人口、身份、居留和地点登记；
2. 公共行政事项分类、办理与转介；
3. 地方行政授权、责任和中央复核；
4. 行政申诉、纠正和档案追踪。

登记窗口、档案、表格、排班和回执属于行政机构日常运行，不分别建立科技。

### 4.3 警察

玩家只决定：警力投向；重点地点和路线；重大案件资源；紧急处置是否启动。

保留八项实际能力：

1. 报警受理、事件分级与调度；
2. 巡逻、现场隔离和初步处置；
3. 案件调查与跨地协查；
4. 现场勘查与证据连续保管；
5. 道路交通、路线安全与事故处置；
6. 沟通降级与比例用力；
7. 临时羁押、健康保障与司法移交；
8. 投诉、纪律调查与外部复核。

这八项不能再压成“警务现代化”或“警务权利保障”一项科技。精简发生在删除重复的立案记录、值班排班和日常交接节点，而不是合并调查、证据、用力、羁押和监督原理。

### 4.4 法律与最低司法

玩家只决定：是否颁布基础法律；是否提供司法复核资源；积压案件和申诉如何优先处理。

保留的实际能力：

1. 法律文本、适用对象和生效程序；
2. 案件受理、证据审查和裁断记录；
3. 羁押、搜查、财产处置和行政措施的司法复核；
4. 申诉、纠错、赔偿建议和公开结果。

十万人阶段不建立完整刑罚体系、复杂法院层级、独立检察体系和长期监狱模拟；需要时以后单独扩展。

## 5. 政务对象不能因为四个核心逻辑而合并

### 5.1 必须独立的工程

1. 公共行政服务厅建设工程；
2. 财政国库与档案安全改造工程；
3. 聚居点警务站建设工程；
4. 区域警务调度中心建设工程；
5. 证据保管与基础检验室建设工程；
6. 临时羁押与司法移交设施建设工程；
7. 最低司法复核与申诉服务设施建设工程。

这些设施可以位于同一政务园区，共享供电、警卫、道路和部分后勤，但仍分别建设、验收、损坏、停用和维护。

### 5.2 必须独立的法令

1. 税费义务、减免与征收法；
2. 公共预算、追加与决算法；
3. 公共采购、合同与验收法；
4. 人口身份、居留与行政服务法；
5. 警察职责、权限与比例用力法；
6. 案件登记、调查与证据程序法；
7. 道路交通与公共路线安全法；
8. 临时羁押、健康保障与司法复核法；
9. 行政申诉、警务投诉与纠正责任法。

不建立“现代政务法”“综合治安法”或“财政行政一体化法”。

## 8. 组织与设施怎样精简

- 一个系统原则上只保留1个中央责任机构、1—3类专业运营机构和必要的地方实例；部门、科室、岗位和值班组不再各自成为组织类型。
- 地方行政中心、警务站、学校、医院、工厂和公用设施按地点生成实例，不因有十个地点就创造十种机构类型。
- 园区和综合服务中心只是共址关系。共址后的行政厅、警务站、法院服务点、医院、仓库和工厂仍保存各自设施 ID。
- 工程只在建设或实质改造实体时建立；巡检、排班、培训、登记、采购、转运和应急响应是行动或任务，不伪装成工程。
- 法令只保留会长期改变权利、义务、权限或责任的规则；操作手册、质量标准、预算案、采购订单和应急命令不是法令。

## 9. 下一步数据门

R5 不得直接导入原255项候选。下一步必须依次完成：

1. 按本规格对255项逐ID标记`retain_tech`、`operation`、`duplicate_review`或`later_route`；
2. 对99项第2年工厂产品形成82项保留表和17项类型修正；
3. 用十万人、52,000岗位、45个标准工业人力容量当量、约200个可协调生产单元和70—110个物理场址检查每项产品是否存在合理生产位置；
4. 再把通过的实际科技、独立产物、前置和解锁关系写入R5；
5. 最后重算科研点并生成新的固定展开PDF。

未完成逐ID映射前，普通两年124项、后期19项和82项第2年产品是精简接入目标，不得伪称R5已冻结。
