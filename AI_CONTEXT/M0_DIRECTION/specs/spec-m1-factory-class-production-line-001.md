# M1 第2年工厂类别、单一产品生产线与养护边界

## 1. 第一规则：工厂是容量类别，生产单元承接明确订单

本规格撤销“一个产品名称对应一座专厂”和“一个工厂同时生产一组产品”两种做法。生产尺度由`SPEC-M1-PRODUCTION-SCALE-WORKSHOP-FACTORY-PRODUCT-VISIBILITY-001`修订为五层对象：

```text
工厂类别
  → 真实厂址实例
      → 可独立协调的生产单元
          → 明确生产订单/配方
              → 一个明确产品或一个明确型号
```

- `工厂类别`是战略层工业容量分类，用于汇总同类厂房、动力、设备、岗位和调度能力；它不是科技，也不是产品。
- `厂址实例`是真实存在的地点，保存岗位、能源、公用设施、设备、损坏、维护和可容纳生产单元数量。
- `生产单元`是生产分配的最小工业能力，可以是数人作坊、机加工工段、装配线、窑炉组或连续生产装置。
- `生产订单/配方`只增加一个玩家可管理的产品库存或完成一个离散设备订单；停线、换线、熟练度、原料和质量记录都归明确订单及其生产单元。
- `产品`是玩家值得独立管理的供给单位，可以是单件产品，也可以是经尺度审查通过的标准化零件组、耗材组或成套装备。它必须能够入库、交付、消耗、装备或作为下游投入。

同一厂址可以容纳多个生产单元，同一单元也可以顺序执行多份相容订单，但不得用厂址或单元名称把产物合并。食品加工场址可以同时容纳谷物磨制单元和罐藏主食单元；订单分别结算，绝不产生“食品与罐头容器”这种混合产物。

一个产品不要求永久独占一座物理工厂。它只要求实际投产时至少获得一个相容生产单元的非零工时份额；同一厂址可以并行运行多个单元，同一单元也可以在明确订单之间轮产。因此产品目录数量不等于专用厂房数量。

## 2. 借鉴边界

- 借鉴《钢铁雄心 IV》：工业容量被分配到具体生产线；生产线保存换线与熟练度，而不是每种装备都先发明一种新的“工厂建筑”。
- 借鉴《群星》：界面上先用产业类别表达经济结构，再由下层岗位和产物完成真实转换。
- 本项目额外保留真实厂址、人口岗位、能源、公用设施、原料、污染、安全、维修和物流；不能只靠一个抽象工厂数值生成产品。

这不是照搬两款游戏的数值。第2年只冻结分类和产物关系，不确定工厂数量、容量、建设月份、产量或换线损失。

## 3. 不能混用的对象

| 对象 | 正确类型 | 说明 |
|---|---|---|
| 军营 | 军事设施 | 驻训、生活和值勤地点，不生产装备 |
| 武器库、弹药库 | 仓储设施 | 保管和发放产品，不生产产品 |
| 军事工厂 | 工厂类别 | 容纳枪械、弹药、工兵装备等独立生产线 |
| 发电站、取水站、矿场、农田 | 资源或服务设施 | 提供能源、原料或服务，不属于制造工厂容量 |
| 维修中心 | 工业服务设施 | 恢复原产品状态，不凭空生成一种“维修产品” |
| 工业园 | 共址关系 | 表示多个厂址共享道路、电力、仓储和消防，不替代工厂、生产线和产品对象 |
| 工艺、配方、标准、生产履历 | 方法或记录 | 可以解锁、约束或证明生产，但不能作为库存产品 |

## 4. 产品尺度门

1. 一条生产线只增加一个玩家可管理的`product_id`，但该产品可以是通过尺度审查的标准化供应组。
2. 螺栓、螺母、螺钉和垫圈合并为`基础紧固件`。它们共享原料、设备、质量体系、使用场景和短缺后果，分别库存不会形成值得玩家处理的战略选择。
3. 只有同时满足以下条件的细小物件才允许合并：属于同一工厂类别；主要工艺和设备相容；主要使用者相近；缺少其中一种时的游戏后果可由同一供应缺口表达；玩家通常不会为它们分别调整优先级。
4. 出现以下任一情形就必须分开：需要不同工业类别或危险许可；独立短缺会改变玩家决策；具有明显代际或型号里程碑；储存、运输、维护或使用方式显著不同；可以分别停产而产生不同战略后果。
5. `基础衣物产品`、`通用工业仪表产品`、`保存食品产品`仍然过宽，因为它们跨越不同用途、生产方法或短缺后果；不能借“适度合并”恢复成万能库存。
6. `操作包`、`工兵装备套装`、`基础紧固件`可以作为一个产品，前提是按统一标准成套或按标准比例入库、配发和补充；内部规格留在配方与质量记录中。
7. `合格批次`是同一产品的一批质量状态，不另建产品；产品名不得把“合格批次”当作物品本体。
8. `加工线`、`装卸站`、`连续供给`、`取水工程`、`总成大修`不是产品，必须分别归入生产线、设施、服务、工程或行动。
9. 同一产品的正式型号独立库存；同型号的微小工艺修订只更新生产标准，不无限增殖产品。

## 5. 第2年工厂类别与生产线目录

`来源状态`含义：

- `直接`：R4 已有一个可对应的原子产品结果，名称只需去掉“合格批次”等质量状态。
- `拆分`：R4 有集合或并列产物，必须拆成多项产品结果。
- `聚合`：R4 的多个细项在战略层没有独立决策价值，合成一个玩家管理的供应单位，内部规格继续保存。
- `补项`：终点能力已经要求该产品，但408项主线没有明确的产品结果，需要返回科技—产物层补齐。
- `重分类`：R4 当前把方法、生产线、服务或记录标成产品，本行给出正确的产品对象，原对象另行改类。

## 6. 罐、食品和罐藏食品的正确关系

```text
炼钢厂：标准钢板
  → 民用工厂的金属包装线：空金属食品罐
      → 食品加工厂的罐藏主食线：罐藏主食

玻璃厂：标准玻璃容器（内部订单为储存罐）
  → 食品加工厂的腌制蔬菜线：腌制蔬菜

食品加工厂：脱粒谷物
  → 食品加工厂：谷物粉或干燥谷物
      → 储存、配给、贸易或进一步罐藏
```

- 空罐是包装产品；罐藏主食是食品产品。
- 食品线消耗空罐后，不把空罐再次计作副产物。
- 没有容器时，食品加工仍可生产谷物粉、干燥谷物等不依赖罐装的产品；只有相应罐藏线停产。
- 没有食品时，包装线仍可生产空罐入库，但不能凭空形成罐藏食品。

## 7. 零件与养护怎样接入而不重新混合

### 7.1 零件

- 基础紧固件、基础传动件、通用滚动轴承、通用工业阀门等直接作为玩家管理的标准化供应组；内部型号、尺寸和配比由订单、配方与质量记录自动处理，不再生成几十种玩家库存。
- `通用机械件覆盖`、`电气与仪表件覆盖`等更高一层指标只是库存汇总视图，不是生产线产物。系统从已经适度聚合的供应组计算覆盖。
- 型号专用备件包可以作为一个明确产品，但必须绑定产品家族和适用型号；不得存在没有适用对象的万能“八类备件产品”。

### 7.2 养护

- 日常保养、定期维护、大修和再制造是行动与服务，不是新产品。
- 维修完成后，原产品从`待修`或`大修中`回到`可用库存/已部署`，产品 ID 不变，保存维修后的寿命、可靠性和更换件记录。
- 只有改造到新正式型号并通过重新定型验收时，才从旧型号库存转为新型号库存。
- 维修中心按机械、电气、车辆、医疗、通信、武器等专业形成设施与岗位，不计入十二类制造工厂容量。

## 8. 对 R4 科技—产物数据的修订清单

本规格不把错误静默改名，R4 至少需要下一轮数据修订：

1. 把`标准螺栓与螺母`和`标准螺钉与垫圈`聚合为`基础紧固件`；把过细的传动件、轴承、阀门、工装、周转容器、玻璃容器、预制构件和部分医疗用品按第4.1节形成可管理供应组。
2. 继续拆分`基础衣物产品`和`通用工业仪表产品`等跨用途集合；“适度聚合”不能掩盖工艺、用途或短缺后果不同的产品。
3. 把`蛋白食品初级加工线`、`装卸站`、`工业热力连续供给`、`可编程逻辑`、`值班通信`、`总成大修`等移出产品类型。
4. 为食品、空金属罐、基础衣物、分级骨料、砖、钢坯、钢管、实体机床、低压配电柜、推车、自行车和车辆维修总成补充明确产品结果。
5. 把“合格批次”改成产品批次状态；产品本体保留独立名称和稳定 ID。
6. 每项新产品必须回连一个真实支持它的科技、工程或既有成熟能力；不能为了填表把无关科技挂成来源。

在上述修订完成前，本目录是终点关系与返工规格，不宣称 R4 科技—产物数据已经一致。

## 9. 后续验收门

下一版工厂数据必须同时通过：

1. 每份生产订单恰好增加一个玩家产品 ID；该 ID 可以是通过尺度门的标准化供应组；
2. 每个产品至少有一种相容生产单元；当月实际生产时必须获得一个非零生产单元份额；
3. 每种生产单元只属于一个工厂类别，但可安装于多个真实厂址；
4. 工厂类别没有库存；库存只属于具体产品和型号；
5. 工厂实例和生产单元没有“混合产量”；产量按明确订单分别结算；
6. 过细物件只有通过同工艺、同用途、同短缺后果和无独立决策价值检查才能聚合；
7. 包装、中间品、成品、副产品和废物分别登记；
8. 维修不生成虚假产品，状态变更可追溯；
9. 军营、仓库、试验场、矿场、发电站等不进入制造工厂容量；
10. 科技只解锁资格，真实厂址、生产线、人员、原料、能源、维护和检验齐备后才有产品；
11. 本轮仍不加入月份、建设顺序、生产量、建设成本或工厂数量。
