# M1科技正文逐项串行打磨与通过闸门

## 1. 第一规则：一个科技没有通过，不得进入下一个

R7不再先生成整批正文、再用空字段、精确重复和关键词扫描宣称通过。五百三十九项科技按稳定顺序逐项进入同一条串行管道；任一时刻只允许一项处于写作或审查状态，后续全部锁定。

```text
读取单项完整事实
→ 第一层执行 fact_gate，判断科技是否应当存在
→ fact_gate 未通过：停在结构修正，不生成正文
→ fact_gate 通过
→ 第三层按内容选择自由格式正文
→ 第一层执行 prose_gate，独立审查内容与阅读结果
→ prose_gate 未通过：退回同一科技重写
→ prose_gate 通过：提交用户审阅
→ 解锁下一科技
```

一次退回不允许只替换几个同义词。退回原因必须指向能力表达、因果、现场侧面、事实越界、相邻科技混淆或模板复用中的具体一项；下一稿必须重新解决该问题。

## 2. R6文字状态撤销

`M1-L1-515`曾以“科技正文精确重复为零、禁用模板命中为零”作为R6文字通过证据。用户截图证明该证据不能识别以下失败：

- 多项正文共享同一种句法和抽象结论，只替换科技名称与领域名词；
- 正文复述科技名、效果栏或解锁项，没有解释实际掌握的能力；
- “世界内侧面”写成作者评论、流程劝诫或岗位责任总结，没有具体世界变化；
- 句子语法正确、字段齐全，但遮住科技名以后可以套给大量其他科技；
- 自检字段统一写“二审通过”，却没有逐句证据。

当前R6数据仍作为科技ID、名称、前置、科研点、类型、产物和关系的来源；其中`body`、`second`、`check`与`text_source`全部退回为`returned_for_r7_sequential_review`，不得直接接入玩家页面。

首轮实测已发现：

| 模板片段 | R6命中数 |
|---|---:|
| `形成可交接的结果` | 39 |
| `实际采用仍需要` | 39 |
| `不替执行者作出现场决定` | 29 |
| `没有减少实际工作` | 14 |
| `无法继续藏在口头交代里` | 14 |
| `能够接续处理，也必须承担` | 14 |
| `从失败记录和相互矛盾` | 13 |

这些数字只证明旧验收失效，不表示没有命中这些短语的正文自动合格。R7逐项审查必须覆盖全部五百三十九项。

## 3. 一个科技作为完整审查单位

每次必须同时读取：

1. 稳定科技ID与完整名称；
2. 科技类型与该类型在世界中的含义；
3. 全部直接前置与直接后继；
4. 科研点、实体条件与证明方式；
5. 每一项独立解锁对象；
6. 所属系统规格中的原始定义；
7. 相邻科技的名称、能力和产物，防止互相吞并；
8. 旧正文，只作为失败证据，不作为必须保留的句子。

若以上任一事实缺失，返回`BLOCKED_SOURCE`。若发现科技本身是总结、行政动作或错误聚合，返回第一层重新设计科技，不得用文字掩盖对象错误。

名称先于正文进入硬门：玩家可见科技名称最多七个汉字，不得含标点、空格、字母或数字。名称出现逗号、顿号等并列符号时，当前对象自动退回`fact_gate`；先判断它是一项统一能力还是多项科技，再决定重命名、拆分或合并。禁止只删标点、硬压成七个字或用空泛总称掩盖聚合。

每项科技同时维护内部事实问题账。确定性错误仍返回并阻塞正文；只有必须结合远处分支、整体密度、玩家尺度或整树玩法价值才能判断的问题，才可进入`pass_with_tree_review`。标签至少包含科技ID、问题类型、证据、相关节点、是否阻塞、建议动作与提出轮次。

## 4. 能力内容的通过门

能力内容必须成为一段可以脱离效果栏独立成立的科技正文，使玩家从技术事实、对象关系、器物变化、判断尺度或历史意义中自然理解“科技完成后改变了什么”。它不能只是把审查答案改写成`某主体能够……`。它可以是一句、多句、对话、记录、叙述或与世界侧面合并的其他形式；句数和格式不是门禁。以下内容条件必须同时成立：

### 4.0 正文身份硬门

- 科研正文强制禁止以`聚居点`起手，包括`聚居点能够`、`聚居点从此能够`、`聚居点可以`及近义形式；
- 不得用`文明／国家／社会／生产体系能够……`机械替代聚居点，继续保留说明句骨架；
- 直接效果列解锁，正文写科技本身。完全严肃科技到正文结束；只有笑话或黑色幽默资格成立时才增加第二行，且第二行只承担笑点或黑色后果；
- 事实正确、效果明确、语言顺畅，仍不足以证明它是正文。读起来像卡片说明、设计解释或审查答案时，直接退回重写。

### 4.1 能力身份

- 玩家读完能够自行说出这项科技改变了什么，但正文不替玩家直接回答审查题；
- 写的是方法、设计、工艺、标准、组织、发现或试制能力，不是“加强、完善、现代化、系统化”；
- 不用科技全名充当谓语，不写“通过某某科技形成某某结果”。

### 4.2 内容核心

- 写出足以区别本科技的真实能力结果；不规定必须出现几个对象、判断条件或处理关系；
- 只写玩家需要理解的核心，不把内部工序、字段、输入清单或解锁清单改写成长句；
- 方法尺度必须与科技一致：不能把一次现场行动写成科研，也不能把多个独立科技重新揉成一项。

### 4.3 结果边界

- 说明掌握方法后什么行动、产品、工程、设施或组织资格变得可行；
- 科研完成不等于调查、施工、生产、部署或颁布已经发生；
- 不虚构具体地点、人物、事故、批次、产量、伤亡或历史成绩；
- 不承诺节点没有解锁的产品、工程、法律权限或社会状态。

### 4.4 非复述

- 不能重复效果栏的“开放：……”；
- 不能把五个解锁名用连接词串成正文；
- 遮住科技名以后，正文仍必须只能指向这一项能力，而不能套给同领域十几个节点。

## 5. 第二行的通过门

第二行不是科研卡常规字段。完全严肃科技禁止第二行；只有当前科技采用笑话或黑色幽默时才进入本节审查。

### 5.1 只选一个笑点或黑色后果

可以选择：

- 一个岗位实际怎样改变工作；
- 一个居民日常遇到的具体变化；
- 一处设施、路线、产品或边界怎样改变去向；
- 一次调查、维修、生产、交付或制度执行中出现的可见差别；
- 一句有明确说话者位置、但不需要虚构姓名或机构的短对话。

不得在同一段里依次罗列技术、产业、社会、政治和生活的全部影响。

### 5.2 用事实呈现，不替玩家下结论

- 写“谁看见了什么、因此怎样处理”，不写“这说明技术很重要”；
- 让具体动作或结果承担意义，不用“必须承担后果”“终于有据可查”“不能省略”等万能收束；
- 如果科技只开放一种方法而尚未实际采用，使用不会冒充既成事实的表达；不能擅自宣布某地已经建成或某次事故已经发生。

### 5.3 与正文分工

- 正文说明科技本身；第二行只承担笑点、荒谬错位或黑色后果；
- 第二行不得换一种说法复述能力结果，不得补充严肃画面、历史意义或影响总结；
- 第二行中的人物、岗位或场所必须由科技产物、实体条件或所属系统自然推出，不能为了气氛临时拉来；
- 当前科技没有合格笑话或黑色幽默时，删除第二行，不填写占位说明。

## 6. 两层串行审查

### 6.1 事实层 `fact_gate`

事实层只判断科技是否应当作为一个独立节点存在，不评价正文，也不生成修辞示意。必须检查科技身份、相邻差异、前置知识与产业条件、全部解锁对象、科研与施工／生产／调查／制度实施的边界，以及删除节点后玩家是否失去独立里程碑。

事实层首先检查名称：最多七个汉字、没有任何符号、只指向一个统一能力。任一条件不满足即`fact_gate: return`。名称含逗号或顿号时，不得先行生成短名；必须先证明并列内容不可分割，否则拆成独立节点。

- 未通过：`fact_gate: return`或`fact_gate: blocked`，禁止第三层创作正文；
- 通过：`fact_gate: pass`，只代表当前对象允许进入文字创作；
- 暂时通过并进入整树复审：`fact_gate: pass_with_tree_review`；必须已经登记一个非阻塞的`MERGE_CANDIDATE`、`REMOVE_CANDIDATE`、`DEMOTE_CANDIDATE`、`SCALE_ERROR`、`DUPLICATE_MILESTONE`或`LOW_GAME_VALUE`疑问，或者已有active amendment修复了当前项的`PREREQUISITE_ERROR`与`UNLOCK_MISMATCH`；`SPLIT_CANDIDATE`、未修复的前置或解锁错误以及`SOURCE_MISSING`不得暂时通过；
- 漂亮正文、已有旧稿和先前审查成本都不能替事实错误补身份。

### 6.2 文风层 `prose_gate`

文风层只处理已经`fact_gate: pass`的玩家正文。下表原G1—G8继续作为诊断维度，但不得再合并科技事实与文字质量后给出一个笼统“通过”。事实正确、语法无误、效果清楚，仍不足以证明正文合格。

每项科技必须留下逐项证据，禁止只写“通过”。

| 闸门 | 必须回答的问题 | 失败示例 |
|---|---|---|
| G1 科技身份 | 这项科技究竟掌握什么？ | 只说统一、完善、形成体系 |
| G2 相邻区分 | 它与直接相邻科技的边界是什么？ | 把地表危险勘察、区域划定和住区设计写成同一项 |
| G3 正文能力 | 正文是否把独特能力结果放在内容中心？ | 重复科技名、效果栏或先讲完整方法 |
| G4 世界侧面 | 若存在世界侧面，是否具体且必然相关；若没有，是否没有硬造？ | “岗位能够接续处理并承担后果” |
| G5 事实边界 | 是否把研究资格写成已经实施的结果？ | 宣布某聚居点、工厂或批次已完成 |
| G6 不可替换 | 换成另一科技名后原句还能否成立？ | 任意调查、标准或工艺都能套用 |
| G7 语言质量 | 是否自然、清楚、没有报告腔与模板落句？ | “形成可交接结果”“实际采用仍需要” |
| G8 正文身份 | 这是一段科技正文，还是把效果与审查答案写成说明？ | `聚居点能够……`、换成`文明能够……`的同骨架句 |

文风层必须特别执行G3、G4、G6、G7和G8；任何一项失败即`prose_gate: return`。像说明书、培训材料、审计报告、效果解释或同义重复的文字，不得因`fact_gate`已经通过而放行。

### 6.3 用户与下一项边界

只有`fact_gate: pass`或`pass_with_tree_review`与`prose_gate: pass`同时成立，当前正文才能以`review_candidate`提交用户。用户逐字接受以前不得标记`accepted_verbatim`。当前项停在任一层时，下一项保持锁定。

`fact_gate: pass_with_tree_review`在单项文字阶段按事实通过处理，但候选必须携带内部问题标签，且不得标记结构已接受。它只允许继续完成可读材料，不构成保留该节点的最终决定。

### 6.4 全部正文完成后的整树合理性复审

全部科技获得可读正文以后，另开一次覆盖全树的游戏设计复审。复审不得只处理问题标签；所有未标记节点也必须与相邻分支、产物、工程、政策和玩家操作尺度重新比较。

每项最终只允许提出一种主裁决，并可附带必要的边修正：

- `KEEP`：保留为独立科技；玩家失去它会失去明确能力或文明里程碑；
- `MERGE`：与一个或多个节点合并为同一玩家里程碑；必须说明统一能力、承接的全部解锁与科研成本；
- `SPLIT`：当前节点实际包含多个不可互换的科技；必须分别说明每项能力和解锁；
- `REMOVE`：现实中虽有学习成本，但游戏中没有独立决策或进步感；
- `DEMOTE`：下沉为其他科技的解锁、工程、设施、产品改型、组织运行、政策、法律或法令；
- `REWIRE_PREREQUISITE`：节点保留，但前置或交叉关系不成立；
- `REWRITE_UNLOCK`：节点保留，但直接效果包含重复、越级、缺失或错误对象。

复审至少检查：独立玩家决策、可感知里程碑、相邻重复、真实前置、产物与工程承接、资源和科研难度、产品代际与型号进步、节点密度、玩家理解负担，以及该内容是否更适合其他系统。精简不能把真正不同的生产方式、装备代际、战术能力或文明跃迁重新合成方向总结。

整树复审只形成结构提案。任何裁决改变节点时，相关名称、正文、科研点、解锁、前置和边全部转为待重新审查；用户确认前不得修改正式科技JSON或把受影响正文继续标为可接入。

## 7. 状态机与审查账

每项科技只允许以下文字状态：

| 状态 | 含义 |
|---|---|
| `locked` | 前一科技未通过，不得开始 |
| `source_check` | 正在核对完整事实 |
| `fact_returned` | 事实层失败，回到拆分、合并、删除、前置或解锁修正 |
| `tree_review_tagged` | 单项事实当前成立，但已登记整树结构复审标签 |
| `drafting` | 第三层只写本项候选 |
| `prose_review` | 第一层在事实层通过后独立审查实际正文 |
| `prose_returned` | 文风层失败，必须重写当前正文 |
| `candidate_pass` | 两层均通过，等待用户判断 |
| `accepted` | 已按当前授权完成最终接受，可固化到R7 |
| `blocked_source` | 上游事实不足，停止本项及后续 |
| `blocked_thread` | 正式文字层不可用，第一层不得代写 |

审查账必须记录：科技ID、轮次、输入事实指纹、旧稿问题、事实问题标签、标签证据、相关节点、是否阻塞正文、建议复审动作、候选正文、候选世界侧面、G1—G8逐项证据、退回理由、最终状态、负责第三层任务与第一层审查时间。

第一层为沟通临时写出的改句必须标记`discarded_review_explanation`，不得进入正向参考、第三层提示、正式候选或玩家数据。
