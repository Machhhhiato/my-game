# M1 第2年终点对象独立性、效果与关联审计

> 工厂部分已被 `SPEC-M1-FACTORY-CLASS-PRODUCTION-LINE-001` 取代。下文第4节和“42项独立生产工厂”只保留为第一次审计的历史证据，不再作为当前工厂模型；设施、法令、政策、状态及其他对象的审计结论仍继续有效。

## 1. 审计目的

本审计逐项检查 `SPEC-M1-YEAR-TWO-END-STATE-001` 中的24类工厂、34类设施、14项法令、12项政策和18项状态，并补查两年主线开放的组织、协议、编制与训练对象。

本轮仍只审查第2年终点，不安排建设顺序、月份、成本、月产量或发展过程模拟。

## 2. 独立项判定规则

一个终点对象只有同时满足以下条件才可原样保留：

1. 只有一个主要职责或一种连续服务；
2. 可以单独建设、颁布、启用、停止、损坏或撤销；
3. 拥有自己的输入、岗位、效果、维护或执行机关；
4. 名称中没有用“与”“、”“及”连接可分别成立的对象；
5. 其效果不会因为其中一个子对象缺失而仍被错误判定为整体成立。

允许多个独立对象共址、共用能源、仓储、管理或检验，不因此把它们合成一个对象。

## 3. 关联类型

| 关系 | 含义 |
|---|---|
| `生产依赖` | 工厂需要的原料、能源、中间品、设备或维护对象 |
| `服务依赖` | 设施向哪些地点、人口、工厂或组织提供连续服务 |
| `法律约束` | 法令规定适用范围、权利义务、安全或质量边界 |
| `政策作用` | 有限期政策临时改变哪些对象的优先级、范围或资源分配 |
| `状态证据` | 对象的实际运行记录可以证明哪些世界状态成立 |

科技到对象仍是“开放资格”关系，不进入本表的运行效果。

### 4.1 工厂审计结论

- 原24项中：9项保留、14项拆分、1项重分类。
- 本次把产品、生产线和工厂身份混为一体，因此“42项独立生产工厂”结论撤销。
- 当前模型改为12类工厂容量、真实厂址实例和逐项单一产品生产线；维修与再制造继续归工业服务设施。
- 同址工业园只保存共址关系；运行、停机、换线、产品和维护分别落到厂址实例与生产线。

### 5.1 设施审计结论

- 原34项中：6项保留、27项拆分或拆分后重分类、1项整体重分类。
- 修订后预计形成66类独立设施；另分离出水务维修、运输调度、道路养护、公共卫生监测、外交和贸易等组织，以及库存位置记录。
- 网络设施可以由多个物理节点共同组成，但网络状态不能替代各关键节点的损坏、容量与维护状态。

## 10. 关联完整性检查

### 10.1 工厂关联门

修订后的每项工厂必须至少关联：

1. 一项能源或公用设施；
2. 一项原料或中间品来源；
3. 一项质量/安全法令；
4. 一项维修设施或备件路线；
5. 一项产品或服务对象；
6. 一项可由运行记录证明的状态。

枪械厂和弹药厂还必须分别关联武器管理、爆炸品安全、试验场和军需补充状态，不能只互相关联形成封闭循环。

### 10.2 法令与政策关联门

- 每项法令必须有执行机关、适用对象、权利义务、违规/纠正过程和修订状态；没有这些字段的“法令”降为标准文件。
- 每项政策必须有上位授权、触发条件、作用对象、期限、资源代价和结束条件；没有具体问题时不得永久常开。
- 法令之间不存在直接互斥；冲突由上位法、适用范围和紧急授权解决。
- 政策可以争夺同一人员、能源、材料、运输或预算；这类竞争进入资源限制器，不建立任意的互斥标签。

### 10.3 状态关联门

- 每项基础状态至少需要两个不同来源的实体或运行证据；单一建筑、单一库存或单一记录不得成立国家状态。
- 汇总状态只读取基础状态，不直接读取科技完成列表。
- 系统不变量不进入玩家可获得状态，也不提供奖励；违反时属于数据错误或账本冲突。

## 11. 主要关系链样例

```text
玻璃原料矿物分级等科技
  → 开放玻璃厂相关工程与产品资格
  → 玻璃厂实体建成并由能源、矿物、运输和质量体系支持
  → 生产容器玻璃、平板玻璃和仪表防护玻璃
  → 支撑食品罐藏、耐久住房、医疗器械和仪表工厂
  → 连续批次与复产记录形成“玻璃可复产”状态证据
```

```text
人口需求核算等科技
  → 开放配给规则设计和执行记录
  → 紧急配给授权法提供长期权限边界
  → 玩家在食品短缺时颁布紧急食品配给政策
  → 行政设施和食品仓库执行，生成资格与批次配给记录
  → 政策结束后记录保留，但政策效果停止
```
