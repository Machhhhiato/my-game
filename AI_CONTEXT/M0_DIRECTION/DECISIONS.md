>
> 这些决定约束后续方向讨论；在独立同步聊天将其写入项目冻结规格前，不得被实施聊天直接当作已冻结任务包。

## D-M0-DIR-001 · GitHub 对话接力协议

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U002`、`M0-S001-U003`
- 决定：
  - GitHub 是跨电脑、跨聊天、跨项目外壳和跨终端的唯一传输层。
  - 使用固定分支 `context/m0-direction`。
  - 一场聊天对应一个 session；保存可见原文和可审计理由。
  - `ACTIVE.md` 作为热接续卡，session 作为追溯来源。

  - 依赖 ChatGPT Project、聊天同步或云项目。
  - 一份由两台电脑共同无限追加的单体聊天文件。

## D-M0-DIR-003 · 设计必须先写具体玩法，再允许总结

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U008`
- 决定：
  - 项目依赖 AI 进行大部分设计与制作，因此所有会话必须使用一致、简洁、显而易懂的表达标准。
  - 设计内容必须先写玩家什么时候遇到、看见什么、能做什么、花费什么、系统如何判断、成功或失败后发生什么。
  - 不允许用“闭环、赋能、张力、战略纵深、能力建设”等抽象总结替代尚未写清的对象、动作、条件和结果。
  - 总结只可放在具体规则之后；内容层、文本层和代码层都不得自行猜测上层没有说明的设计。
- 后续确认：四层会话、共享白话规则与固定交接格式已由 `D-M0-DIR-004` 确认采用。

## D-M0-DIR-004 · 四层固定映射与一句话启动

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U009`
- 固定映射：
  - 第一层：方向与系统设计；
  - 第二层：故事、任务与临时事件；
  - 第三层：玩家可见文字；
  - 第四层：代码操作、运行与验证。
- 启动规则：
  - 用户在新会话只需输入“你是第一层”“你是第二层”“你是第三层”或“你是第四层”。
  - 这句话只选择层级；实际职责、当前里程碑、上游版本、允许写入范围和禁区必须从 Git 协议文件读取，不能依靠聊天记忆。
  - 收到启动语后只进行只读检查，不自动创作、修改、提交或推送；检查通过并返回 `READY` 后再等待用户任务。
  - 启动回执必须显示项目、里程碑、层级名称、协议版本、Git 基线、允许范围和禁止范围。
- 安全失败：仓库错误、协议缺失、本地落后或分叉、上游未确认、层级冲突或模型能力不足时不得继续，必须报告具体原因和唯一恢复动作。
- 落地边界：Mac 与 Windows 的项目入口、四张层级规则和跨项目全局路由由独立同步会话创建并实测；本方向会话不执行。

## D-M0-PROD-001 · 为资深玩家本人定制并先免费发布

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U004`
- 决定：
  - 游戏当前首先为用户本人量身定制；用户是资深策略玩家，也是 M0 的第一验收人。
  - 当前不考虑买断、定价或商业回报，不以大众市场转化约束 M0 核心体验。
  - 初版只有在用户本人认可后，才进入首次公开发布。
  - 首次公开发布路径为 Steam 免费游戏。
- 边界：
  - Steam 免费不自动等于 F2P、广告、内购、赛季或持续在线运营。
  - 是否永久免费以及后续商业方式均为 `deferred`。
  - 用户认可优先于外部测试；发布前是否安排少量资深玩家兼容性测试仍是 `proposal`。

## D-M0-PROD-002 · 专业管理形成科技、资产与版图领先

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U005`
- 核心爽点：
  - 拥有更多高科技、技术与资源优势、地图控制、高级资产、奇观、军队、舰船、军舰和航母等可见对象。
  - 通过操作和微调集中资源，抢先突破关键科技，并把领先转化为真实资产和扩张能力。
  - 国家内部资源与政策形成良性循环，在压力和危机前拥有足够储备。
- 设计规则：
  - 重大科技必须沿“研究 → 设计/工程 → 制造 → 部署 → 地图或运行结果”形成可拥有对象，不能只给抽象百分比。
  - 优势允许正向累积：科技促进生产与勘探，资产扩大资源和版图，新增资源反哺科研、生产与储备。
  - 危机是准备度考试；预警、储备、冗余、维护和正常经营应能完整解决问题。
  - 主要选择是顺序、效率、产能、扩张速度和储备目标，不以强制极端匮乏或二元道德困境制造戏剧性。
  - 极端方案只能作为长期失误后的可选应急路径，不能是正常成功路线的必经门。

## D-M0-PROD-003 · 玩家突破与系统自动推进并存

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U006`
- 决定：
  - 玩家可以协调科研、预算和产能，集中资源抢先完成关键科技。
  - 玩家想放松时，系统可以自动推进中间过渡与普通科技，形成看海阶段。
  - 自动科研必须受玩家选择的科技领域倾向约束，并允许随时接管。
- 待冻结提案：
  - 双层科研分为手动“重点突破”和自动“领域推进”。
  - 领域倾向先使用重点、正常、维持、暂停四档，不在 M0 使用复杂百分比面板。
  - 核心突破、路线分叉、重大资产和不可逆制度不允许系统擅自决定。

## D-M0-PROD-004 · 自动资源必须来自实体体系

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U006`
- 决定：
  - 自动资源获取不能是科研完成后凭空增加的抽象日产量。
  - 每类资源必须有与其性质相符的独立系统或前哨设计，例如农田、给排水、水厂、废墟勘探与回收。
  - M0 第一条链必须到达可日常独立运行、持续向总部输送资源的前哨。
- 通用实体链：资源地点 → 生产/采集 → 当地加工 → 仓储 → 运输路线 → 总部流入。
- 边界：独立运行代表日常自治执行，不代表免维护、无限资源或独立主权。

## D-M0-PROD-005 · 首建形成可复制的标准工程经验

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U007`
- 决定：
  - 每一种前哨或资源工程类型第一次建立时，都要经历选址、探索、场地清理、应用科研、测试、工程建设、试产和稳定验收。
  - 首次稳定运行后，国家获得该类型的生产与工程经验；后续同类前哨只要找到合适选址，就可以由系统一条龙自动完成，不再要求玩家重复操作。
  - 首建的核心挑战是协调有限资源和人力，而不是逐项点击施工步骤。
- 边界：经验消除重复管理，不消除真实的人力、物资、时间、运输和维护成本；超出既有适用条件时仍需要工程适配。

## D-M0-PROD-006 · 地形适配与有限人力构成前哨约束

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U007`
- 决定：
  - 地图骨架必须表达山地、泥地、河边、沙滩、矿产资源、城市废墟等土地与资源条件，并据此约束工程选址。
  - 不同工程有不同的硬性选址要求；农田不能无条件建在城市废墟或山地，矿山必须依附矿藏，废墟回收必须依附可回收遗址。
  - 首建阶段重点考验有限人力在日常资源生产、科研、勘测、工程建设、物流与继续开拓之间的协调。
- 待冻结提案：地图采用区域节点、候选工程地块和交通连接；地块以地貌、水文、资源覆盖、工程风险和交通条件分层表达。

## D-M0-PROD-007 · 下一阶段做到第二座同类前哨自动稳定运行

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S001-U010`、`M0-S001-U011`
- 阶段终点：
  - 做成可从新局连续玩完的 M0 个人完整试玩版；
  - 正式节奏目标为游戏内前 90 日、现实 30–45 分钟；
  - 玩家稳定总部水务，集中科研完成关键突破，制造勘测资产并发现两个工业废墟地点；
  - 第一座工业废墟回收前哨由玩家完整主导首建，稳定后持续回运构件和合金并形成标准工程包；
  - 第二座同类前哨由玩家批准地点、优先级和投入上限后自动建设，最终稳定回运；
  - 结尾保留一段可观察科研、运输、库存和地图优势自动增长的时间，并用一次有预警的压力检验储备。
- 通过条件：无需开发命令可玩完；存档重载保留关键状态；全程有 5–8 次影响进度的操作；第一座确实困难、第二座显著省心；用户本人感到领先是自己协调出来的并想继续扩张。
- 非目标：其他前哨类型、完整科技树、大地图或程序化世界、90 日后长期平衡、战争舰队与航母实际系统、最终美术和 Steam 发布。未来高级资产可以露出目标，但不在本阶段实现。

- 状态：`user_confirmed`
- 来源：`M0-S001-U012`

  - 每次任务或设备交接都必须明确写出下一设备、逻辑 lane、稳定工作 lane、建议会话标题、层级、任务 ID、分支和启动语；不能只写“下一步属于第一层”。
  - 使用 `NEXT_ACTION.md` 保存唯一下一目的地，使用 `SESSION_ROUTING.md` 保存 13 个任务到稳定会话的映射。

  - 用户要求本轮完成指导并推送，因此允许在 `context/m0-direction` 对项目根 `AGENTS.md` 增加最短项目内短语路由，输出 ID 为 `WF-M0-PROJECT-001`。

## D-M0-PROD-011 · 正式 M0 内容门的终点与未达成口径

- 日期：2026-08-20
- 状态：`user_confirmed`
- 来源：`M0-S002-U005`
- 决定：
  - 正式内容门必须同时证明总部供水、食物和维护持续运行且守住安全底线，精密制造与勘测资产实际可用；
  - 玩家完整经历第一处废墟的发现、勘测、路线与风险判断、清理、建设和试产，第一座回收前哨稳定回运；
  - 玩家批准第二处地点、优先级与投入上限后，系统完成第二座同类前哨并稳定回运；自动暂停原因必须可见且可恢复；
  - 第二座稳定后保留连续观察期，期间科研、物流、库存和维护继续自动运行，并用一次有预警、可由正常储备吸收或恢复的压力检验正循环；

## D-M0-PROD-023 · 集中与稳定是资源调配形成的倾向，不是路线卡
