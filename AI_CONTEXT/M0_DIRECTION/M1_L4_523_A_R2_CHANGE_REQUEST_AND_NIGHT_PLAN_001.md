# M1-L4-523-A-R2 退回单与长工作计划

## 一、用户退回结论

`M1-L4-523-A-R1`不接受，退回继续修改。当前版本不得并入主工作区，也不得据此进入`M1-L4-523-B`。

用户指出三项问题：

1. 第一个科技完成后，第二个科技仍要等待第一个科技对应的生产流程，科研与生产被错误串联。
2. 废墟勘测开始后出现自动暂停或看起来已经自动暂停，但页面没有清楚说明原因。
3. 前期生产链未打通时缺少资源回收保底，可能形成资源耗尽后的软锁；需要若干不依赖上游投入、可以恢复基础资源的保底项目。

本机试玩服务已经停止。已加载页面中的运行状态不构成正式存档或产品状态；当前浏览器标签页无法由浏览器控制接口接管，若标签页仍保持打开，关闭标签页即可停止其内存中的页面计时，重新加载因服务已停止也不会继续试玩。

## 二、只读根因核对

### 1. 科研被生产阻塞

确定性根因已经找到：`适配勘测无人机`除科研前置`恢复精密制造`外，还把`prototype-precision-parts`登记为科研的实体前置。科研选择器因此在第一个科技完成后主动停止，直到玩家修复工坊并生产出精密零件试制批。

这违反当前控制基准。科技研究、工程建设和产品生产必须是不同状态机：

- 科研前置只决定知识是否可以继续研究；
- 科技完成解锁工程、设施或产品生产资格；
- 工厂、产线、材料与设备只决定产品能否制造；
- 下游产品不得反过来成为解锁自身科技的科研前置。

修订后，两个科技都在科研队列时，第一个科技完成后的下一结算日必须直接开始第二个科技。即使工坊尚未修复、精密零件库存为零，第二个科研仍应继续；对应产品生产仍由设施、科技和投入分别检查。

### 2. 废墟勘测暂停

干净新档的最小复现没有出现自动暂停：同时运行第一个科研和工业废墟 A 勘测，连续推进十个世界日，勘测项目始终为`active`，情报阶段从方向确认推进到路线确认。

因此不能把用户观察简单归结为一个固定的勘测流程错误。当前实现仍有两个已经确认的设计缺陷：

- 勘测被当作普通 P2 工程纳入统一人员不足和资源安全线，真实存档进入低资源状态时可能被系统自动暂停；
- 页面只把按钮从“开始勘测”改为“暂停勘测”，没有独立显示“勘测中 / 玩家暂停 / 系统暂停及原因”，操作名称和当前状态容易混在一起。

R2必须同时解决运行和呈现，而不是只改按钮：

- 开始勘测后，各情报阶段默认自动接续；
- 系统不得因为与勘测无关的零件库存而暂停勘测；
- 只有生存保障导致实际人员不足、勘测自身的明确条件不足或玩家主动暂停时才能停；
- 任何系统暂停都必须显示唯一原因、恢复条件和是否会自动恢复；
- 当前状态必须单独显示，按钮只表示下一动作。

### 3. 基础资源软锁

当前基础资源中，水和食物已有日常岗位形成持续流入；普通零件也可由旧件维修形成有限流入。但是工程部件和合金只有初始库存，没有前期可重复来源；精密工坊、试制批和无人机都会消耗这些库存。玩家若顺序不当或后续内容扩大，可能在生产链建立前耗尽并失去恢复手段。

R2增加三个内部保底回收项目，正式玩家名称和正文另走第三层文字门禁：

- `floor_common_parts`：恢复普通零件；
- `floor_engineering_components`：恢复工程部件；
- `floor_alloy`：恢复合金。

三项只使用系统分配的人力和工作量，不消耗任何物资投入，不要求科研、工厂或前置产品。它们是低效率、可重复的工程回收行动，不是生产线，也不生成精密零件、无人机或其他里程碑产品。

为了避免把保底机制变成无限资源农场，每项只允许在对应资源低于保底库存线时启动，单次产出把资源推回安全区但不得超过保底上限。玩家决定启动哪一项以及先后顺序；系统只处理人员、工作进度和结算，不替玩家自动批准。

所有回收产出必须进入统一月度资源账，登记为明确流入，并在事件记录中可追溯；禁止直接静默改库存。

## 三、R2冻结设计合同

### 3.1 科研、工程与生产三线分离

| 状态机 | 玩家决定 | 底层判断 | 禁止关系 |
|---|---|---|---|
| 科研 | 科技入队、移出、顺序 | 科研前置、科研容量、科研点进度 | 下游产品和生产批次不得阻塞自身科技研究 |
| 工程 | 是否执行、暂停继续、先后顺序 | 设施前置、场地、系统人员、资源投入、工程进度 | 工程完成不得伪装成科技完成 |
| 生产 | 产品行投入多少工厂 | 科技资格、设施、材料、产能、维护 | 生产不得占用科研队列或替玩家切换产品 |

### 3.2 勘测状态合同

勘测卡必须具有独立的当前状态：`未开始`、`勘测中`、`玩家暂停`、`系统暂停`、`已完成`。`系统暂停`必须携带机器可判定的原因代码和玩家可读恢复条件；不能只有笼统的“已暂停”。

玩家只有两个决定：是否开始、是否暂停。路线、人数、天数和设备调度继续由系统处理。一次开始后，方向、区域、路线和现场阶段自动接续，不要求逐阶段确认。

### 3.3 保底回收合同

- 项目数固定为三项，对应普通零件、工程部件、合金；不把食物、水、精密零件和装备混入。
- 每项是独立项目、独立产出、独立进度、独立完成记录。
- 项目不消耗物资；只消耗统一工程工作量。
- 只有对应库存低于保底线时可批准；达到保底线后按钮显示不可启动原因。
- 单次完成只补至保底区间，不得越过上限；具体数值由R2在资源压力测试后冻结。
- 不自动开始，不自动改优先级，不替玩家批准。
- 产出进入月度资源账和事件记录，存档重载后完全一致。

## 四、长工作计划

本计划按一个连续六至八小时批次设计。用户随后把最终目标扩展为“做完一个自循环产业、约一千人的Demo”，并授权今晚自行推进；完整新增合同见`M1_L4_523_A_R2_1000_LOOP_NIGHT_EXECUTION_001.md`。R2获得执行授权，但仍须由职责正确的第四层任务完成。

### 阶段0：基线封存与问题复现，约三十分钟

1. 复用当前接替工作树，不并入主工作区。
2. 记录当前八文件差异、自动测试和浏览器基线。
3. 建立三条最小失败用例：科研被试制批阻塞、低资源勘测暂停、工程部件与合金归零软锁。
4. 明确R2文件白名单；若新增状态字段，先决定存档版本和迁移边界。

完成证据：三条失败用例在旧实现上稳定失败，并能说明失败原因。

### 阶段1：科研与生产彻底解耦，约一小时

1. 删除下游产品作为科研前置的逻辑。
2. 保留纯科研前置关系。
3. 把产品资格检查留在生产状态机，把设施与投入检查留在工程和生产状态机。
4. 更新队列阻塞原因，禁止再出现“科研等待生产自己解锁的产品”。
5. 补回归测试：无工坊、无精密零件时第二科技仍能研究；无人机产品仍不能提前生产。

完成证据：科研连续推进，生产仍被正确锁定，两边互不污染。

### 阶段2：勘测状态与暂停规则重做，约一小时

1. 从通用工程暂停规则中拆出勘测专属判定。
2. 只保留人员生存冲突、勘测自身条件和玩家暂停三类合法停止来源。
3. 为系统暂停增加稳定原因代码、恢复条件和自动恢复标志。
4. 页面增加独立状态行；按钮只显示下一动作。
5. 连续运行、资源紧张、人员紧张和保存重载四种状态分别验证。

完成证据：正常勘测不会自己停；必须停时玩家一眼知道原因和如何恢复。

### 阶段3：三项保底回收进入统一资源账，约两小时

1. 确定最小数据结构，优先复用通用工程项目、月度账和事件系统，避免建立第二套资源逻辑。
2. 增加三项内部项目定义、低库存启动门槛、工作量、单次产出和保底上限。
3. 完成时把产出记入当月流入，不直接修改库存快照。
4. 允许完成后再次批准，但同一资源同时只能有一个回收项目。
5. 精密零件和无人机继续只能由生产线获得。
6. 通过压力测试调整保底线与产出，使其可以解除软锁，但明显慢于正常生产链。

完成证据：把普通零件、工程部件和合金分别降到零后，玩家都能只靠对应项目恢复到可继续建设的最低水平；无法借此越过精密制造里程碑。

### 阶段4：悬浮面板接线与非技术表达，约一小时

1. 保底项目放入现有工程悬浮面板，不新增独立页面。
2. 每项固定显示目标资源、当前库存、保底线、预计产出、项目状态和开始按钮。
3. 不出现工程队人数、路线、每日工时等微观字段。
4. 本轮先使用明确的系统占位标识；正式名称与正文必须经过第三层文字门禁后才能成为`accepted_verbatim`。
5. 勘测卡同步显示真实状态与暂停原因。

完成证据：玩家能够做出项目和顺序决策，但不需要管理执行细节。

### 阶段5：存档迁移、自动测试与资源对账，约一小时十五分钟

1. 若状态结构改变，升级存档版本并只接受严格旧版迁移。
2. 验证迁移、保存、读取、清档和旧键删除。
3. 覆盖科研连续性、生产锁、勘测继续、三项资源归零恢复、保底上限、重复项目、月结算和确定性重载。
4. 检查任意日执行和跨月执行的资源总账守恒。

完成证据：类型检查、核心模拟、构建和差异检查全部通过。

### 阶段6：浏览器长跑与第一层收回，约一小时

1. 新档直接排入两个科技，观察第一个完成后第二个无需生产流程立即继续。
2. 启动废墟勘测并连续推进完整阶段；测试玩家暂停和真实系统暂停。
3. 在三种基础资源耗尽场景中分别完成保底回收。
4. 检查1920×1080、1366×768和390×844，地图始终可见，面板不越界。
5. 保存、刷新、读取后重复关键操作；浏览器错误和警告必须为零。
6. 第一层独立检查测试是否真的覆盖用户三项问题，不以“构建通过”代替玩法验收。

完成证据：形成R2实现审查和可试玩地址，状态只能是`implemented_verified_waiting_user_review`，不能自动标记接受。
