## 四、第一批实现范围

第一批命名为`M1-L4-523-A`，只完成以下闭环：

1. 把真实日长改为一秒，并保持暂停、倍速、逐日顺序与自然月结算。
2. 把科研改成纯玩家队列：科技卡点击直接入队，队列项目右键直接移出，空队列时待命。
3. 当前科研被移出时，删除该科研项目的未完成进度；已完成科技不受影响；其余队列保持原顺序。
4. 把生产改成固定产品行和持久工厂分配；玩家在产品行直接增减工厂，不再点击确认生产。
5. 工厂总数守恒；材料、人员或设施不足时生产行保留分配并显示真实阻塞，系统不得替玩家改投其他产品。
6. 保留玩家对科技、工程是否执行及先后、产品与工厂数、政策法律法令的战略权力；当前没有真实模型的后三者不在本批伪造。
7. 从玩家可见界面移除逐岗位、科研设施岗位、勘测人数、最多天数、路线和生产细节控制；底层数据继续自动运行。
8. 维持地图常驻和悬浮面板，修正桌面与窄屏布局，不建立独立工程场景或军事地图。

### 生产最小语义

- “投入工厂”是持续命令，不是待确认的表单值。
- 增加工厂后，满足前置的生产行从下一个结算日开始贡献生产进度。
- 减少工厂后只改变后续产能，不回滚已经实际消耗的资源和已经形成的进度。
- 输入不足时该行暂停，分配保留；输入恢复后自动继续。
- 一次性资产达到当前真实资产上限时，该行进入“目标已达”的真实停工状态，工厂仍由该行占用，直到玩家自行撤回；系统不得替玩家转产。
- 本批只接当前产品骨架中真实存在的两条样例，不把样例名称和数值上升为完整 Demo 正式内容。

## 六、强制自动验收

### 时间与结算

- 暂停时真实时间不推进世界日。
- 一倍速一千毫秒推进一天；二倍和四倍仍逐日结算，不跳过自然月边界。
- 连续推进与逐日调用在资源、工程、科研、生产和事件结果上相同。
- 任意日期经过时，未入队科技不会自行开始，未批准工程不会自行开始，工厂不会自行改投产品。

### 科研

- 单击未完成科技后，它立即出现在队列；必要前置的实际队列结果确定且不重复。
- 右键非当前项目只移出该项，不改变其他项目顺序。
- 右键当前项目后，该项目从队列和运行项目中消失，未完成进度归零；下一项只在它本来就在玩家队列中时接续。
- 队列为空时，无论过去领域自动字段为何值，科研都保持待命。
- 已完成科技不能重新入队，也不能被右键动作撤销。

### 生产

- 所有当前可展示产品行始终存在，锁定态也不从列表消失。
- 加减工厂直接改变真实分配，不出现“确认生产”“确认组装”或统一下达按钮。
- 所有行的已分配工厂总和不得超过真实可用工厂数。
- 材料不足、设施未完成或资产上限达到时，阻塞原因来自真实状态；分配不会被系统偷偷改到别行。
- 保存再读取后，生产分配、进度、阻塞和库存保持一致；下一日结果确定。

### 控制范围

- 玩家界面中不存在日常线逐岗位加减、科研设施岗位加减、勘测人数、最多白昼、路线确认、班次、人员、能源、输入顺序、合格率或维护工序控件。
- 工程仍可由玩家开始、暂停和排序；界面可显示进度、已投入物资和占用人力，但不得要求玩家分配工程队。

### 工程质量

- `npm run typecheck`
- `npm run test:m0`
- `npm run build`
- `git diff --check`
- 不得通过删除旧断言、放宽严格存档校验或把错误吞掉来获得通过。
