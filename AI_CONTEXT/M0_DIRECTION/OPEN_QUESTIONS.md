## Q-M0-002 · 前 30–45 分钟的完整体验

- 状态：`partially_resolved`
- 决定者：用户
- 为什么重要：它决定四个情境如何串联，以及 5–8 次取舍是否构成完整体验而非任务清单。
- 已确认核心：专业管理 → 关键科技领先 → 高级资产 → 资源与地图优势 → 良性循环与储备抗危机。
- 已确认终点：第一条链到达第二座工业废墟回收前哨自动稳定运行，并保留一段观察时间。
- 已确认路径：修复精密制造能力 → 制造中心 → 勘测无人机 → 第一座工业废墟回收前哨完整首建 → 构件和合金持续回运 → 第二座同类前哨自动复制。

- 阻塞：情境顺序、七次决策矩阵和玩家可见内容白名单。

## Q-M0-006 · 科研自动化与领域倾向

- 状态：`queued`
- 决定者：用户
- 已确认：玩家可集中突破关键科技；普通科研允许自动推进；自动科研需要领域倾向并可随时接管。
- 当前推荐：
  - 同时存在一个手动重点突破目标和机构自动领域推进；
  - 领域采用重点、正常、维持、暂停四档；
  - 自动策略可选补齐前置、解决瓶颈或沿领域推进；
  - 系统显示后续队列和选择原因，并遵守资源/储备底线；
  - 核心突破、路线分叉和重大资产必须手动确认。
- 需要确认：是否采用这套双层结构与四档倾向。
- 来源：`D-M0-PROD-003`、`M0-S001-U006`。

## Q-M0-007 · 首台套工程、地形适配与自动复制

- 状态：`resolved`
- 决定者：用户
- 已确认：
  - 每类前哨第一次建立都经历完整的选址、探索、清理、科研、测试、建设和试产；
  - 首次成功后形成成熟经验，后续同类前哨在合适地点可由系统自动跑通；
  - 地图土地条件必须限制工程用途；
  - 首建压力主要来自有限人力在资源生产与开拓之间的协调。
- 已确认方向：
  - 将成果定义为可检查适用范围的“标准工程包”，而不是抽象经验加成；
  - 新地点完全匹配时自动复制，轻微差异时自动适配，超出适用范围时重新进入玩家主导的工程变体；
  - 复制仍消耗时间、人力和物资，并服从玩家设置的优先级、投入上限与储备底线；
  - M0 只完整实现工业废墟回收一种远程前哨，用第一座首建和第二座自动复制证明闭环。
- 后续冻结：具体阶段、标准工程包适用条件、暂停恢复和临时数值进入 `M0-L1-104`。
- 决定：`D-M0-PROD-007`。
- 来源：`D-M0-PROD-005`、`D-M0-PROD-006`、`M0-S001-U007`、`M0-S001-U011`。

## Q-M0-008 · 四层 AI 制作会话与白话设计标准

- 状态：`resolved`
- 决定者：用户
- 已确认：
  - AI 容易用总结和高大上词汇代替简单、具体、可执行的设计；
  - 项目大部分工作会依靠 AI，因此必须建立跨会话统一标准；
  - 用户提出四层候选：方向与系统设计、故事与临时事件、玩家文本、代码操作与执行。
- 已确认方案：
  - 采用四层，不另设第五个生产或审查会话；
  - 四层共同读取一份由 Git 保存的白话设计规则、术语表和交接索引；
  - 每层只能消费上一层已确认的 ID 与版本，发现缺失时退回，不能自行补规则；
  - 方向层交系统设计卡，故事层交事件设计表，文本层交带 ID 的实际字符串，代码层交实现与验证证据；
  - 强模型负责方向、关键事件和实现；Spark 负责模板冻结后的批量候选、文本填充和小范围修改；
  - 具体模型名称放在可替换的模型分配说明中，不写死在游戏设计规则里。
- 已确认：采用四层职责、共享白话设计规则、固定交接编号与默认模型分配。
- 已确认启动语：用户只需说“你是第 N 层”；AI 从 Git 协议读取职责，先完成只读检查并返回启动状态。
- 决定：`D-M0-DIR-003`、`D-M0-DIR-004`。
- 来源：`D-M0-DIR-003`、`D-M0-DIR-004`、`M0-S001-U008`、`M0-S001-U009`。

## Q-M0-009 · 下一阶段终点与会话任务拆分

- 状态：`resolved`
- 决定者：用户
- 为什么重要：它决定 M0 是停在设计、水务原型、完整个人试玩还是过早进入 Steam 制作，也决定四层何时交接。
- 已确认终点：
  - 做成一个可从新局连续玩完的 M0 个人完整试玩版；
  - 正式目标仍为游戏内前 90 日、现实 30–45 分钟；
  - 玩家稳定总部水务并准备储备，手动集中科研完成关键突破，同时让普通科研按领域倾向自动推进；
  - 玩家用高科技勘测资产找到两处工业废墟，完整主导第一座回收前哨的选址、清理、科研、测试、建设和试产；
  - 第一座前哨稳定回运构件和合金后形成标准工程包，第二座同类前哨在玩家批准地点和投入上限后由系统自动建成并稳定回运；
  - 结尾保留一段不需频繁点击的观察时间，并用一次有预警、可由储备正常解决的压力验证正循环；
  - 存档、退出和重载后，科研队列、人力排程、前哨阶段、物流和储备规则均能继续。
- 第一层在现有 Mac/Windows 方向 lane 内依次冻结五项，不另开并行方向源：试玩起点与终点；人力资源与压力；地图选址与物流；科研资产与前哨复制；完整纸面试玩和验收表。
- 已确认下游任务顺序：
  1. 独立同步会话落地四层协议和路由；
  2. 第四层只读检查现有代码与系统契约的差距；
  3. 第二层建立主线、任务和临时事件包；
  4. 第三层填写全部玩家可见文字；
  5. 第四层分为基础运行与存档、地图科研与高级资产、前哨物流与自动化、完整接入与验证四个实现会话。
- 明确非目标：Steam 发布、最终美术、完整科技树、其他前哨类型、大地图或程序化世界、90 日后的长期平衡、战争舰队与航母等实际系统；未来高级资产可以显示为目标，但本阶段不实现。
- 任务落点：`ACTIVE_TASKS.md`、`TASK_PACKAGES.md`、`WORKFLOW_BOOTSTRAP.md` 和 `roles/`。
- 当前前置任务：先完成一次性 `M0-L4-000`，让四层会话能从 Git 正确识别任务；随后进入 `M0-L1-101`。
- 决定：`D-M0-DIR-005`、`D-M0-PROD-007`。
