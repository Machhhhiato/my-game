# Always Game 当前状态

> 更新口径：依据项目目录内文档与代码结构建立；未进行本轮玩法或视觉验收的项目不得视为“已验收”。

## 1. 已完成或已冻结的内容

### 世界与内容规则

- 原始世界观、八款游戏科技素材、科技整合、时间线、小说大纲及元年到终局的阶段扩展文档已存在。
- 玩家身份、单一主权中央政府、有限地方执行自治、固定宏观锚点与可变实现路径已确认。
- 系统—剧本六层分离、通用数据契约、工程与地理分层、道路按端点规划等规则已冻结。
- 第一历史阶段“聚居地 → 区域城镇网络”的 R5 内容包已生成：1,000 科技、1,000 工程、20 个三阶段政策家族；R6 玩家文案包对应 1,000 科技、1,000 工程、60 政策版本。
- 科技树已定义为十领域、50 主干/750 分支/200 分级，并包含跨领域知识与已投用工程前置。

### 地图与数据骨架

- R9 已定义类地球自然生成顺序、L5 球面网格、稳定地理引用、连续高程/水文/气候/生态资源派生及工程增量协议。
- 已明确测试世界必须覆盖深海、大陆架、海岸、平原、河谷、高地、高山、森林、荒地、冻原和完整下泄河流。
- 地图美术、城市/工程资产、道路和网络仍以“读取事实层”的方式规划；现有视觉效果不代表最终美术验收。

### 运行原型

- 代码使用 React、TypeScript、Vite、Tauri 架构；旧 v2 地图原型仍保留，可通过 `?map=1` 查看。
- 默认入口已切换为 R10 文字挂机验证层（`src/v2/ui/TextIdleApp.tsx`），其目标是先验证“手动应急积累 → 自动化 → 脱离生存危机”的决策链，再把同一 ID/效果契约接回空间层。
- 文字挂机层已具备目录按需加载、研究/工程自动选择、国策/政策、持续日结算和阶段内容数据接入的代码结构；完整目录不是平铺卡片墙。
- R10 运行时已建立旬级日历、后台日结算、可调度人手、建设物资、持续临时行动、储备失守和每日效果归因的数据字段；这是一套可测试的底层框架，尚未完成最终 UI 与数值体验验收。
- R5 第一阶段的 1,000 科技、1,000 工程与 60 政策版本已全部写入标准 `runtime` 合同：时间、占用编制、启动需求与标准结果由目录提供；R10 不再按卡片类别或 ID 推断这些数值。政策在生效期间也会占用行政执行编制。
- R11 已建立独立的国家模拟内核合同与无剧情回归夹具：统一量纲、作用域、权责、生命周期、操作、标准效果、都市圈汇总、多势力关系、情报观察与因果账本均有类型和纯结算算法；尚未接入 UI、R10 存档或正式内容目录。
- R11 量纲目录已按发展阶段定义展示规则，并提供三个可验证开发存档夹具：起步共同体、统一国家、外交冲突。它们用于回归测试，不是默认剧情或正式玩家存档。
- R11 已提供独立开发检查器（`?kernel=early|unified|conflict`）：可读取三份夹具并推进日期，检查量纲、城市群、外部势力、舰队、战区、操作与因果账本；它不读写正式试玩状态，也不代表最终 UI。
- R12 已将“统一国家”夹具升级为国家级内容纵切片：10 科技、10 工程、10 有期限政策通过能力/设施/网络前置相连；工程完成能创建可维护设施或网络，城市服务覆盖保存在城市作用域。它只用于 R11 开发验证，尚未迁入 R10 默认战役或正式内容目录。
- R13 已将统一国家的既有港口、维修、调度与登记事实接入外交冲突夹具：3 科研、3 工程、1 军事行动、1 港口政策与 2 外交行动可依次改变精确舰艇状态、战备、补给、情报可信度和双边信任。它仍是开发纵切片，不是正式战争系统。
- R14 已把 R12/R13 收束为可安装内容包：内容只声明城市、舰队、关系等功能角色，夹具/战役再绑定实际实体；安装会拒绝错误实体类型和重复操作。现有定义仍有过渡适配层，尚未迁成纯声明式模板，也尚未接入正式战役。
- R15 已将默认文字入口收束为通用首阶段可试玩框架：6 项研究、4 项工程与 2 项政策可从生存应急推进到稳定聚居；研究/工程显示明确结果与阻塞原因，完成项进入档案。千级目录仍为后续数据源，不代表已完成玩家界面接入。
- R16 已补入首阶段试玩指引：界面会基于运行时事实显示当前阶段、下一步可行动目标和阶段检查项；重点记录只保留研究/工程完成、保障风险、恢复与阶段达成。它不改变数值结算，仍等待真实试玩反馈。
- R17 已为首阶段文字试玩接入探索纵切片：三条方向探索会占用勘察人员并按日完成，发现同时保存研究线索和稳定地理引用的工程候选地；首批研究与供给工程因此不能越过探索直接开始。原国策大卡已替换为随真实作业轮播的轻量线稿动态区，国策收纳为紧凑入口。
- R18 已将三条探索方向呈现为迷雾/路线/节点式文字战略图；展示坐标与稳定地理引用分离，空间层可在未来只读取后者。R19 的首批“探索→线索→工程候选地”链已接入基础供水、仓储和维修项目。R20 多路线模拟已验证三种探索顺序与方针均可完成基础设施链；无操作会在第 131 日失守，方针会造成不同的储备压力。
- R21–R22 已将“稳定聚居→区域网络→区域统合”接入可保存的文字阶段：首阶段的人口、保障、建设物资、已完成能力、设施、日历和部分社会指标迁入单一玩家政体的国家内核；区域网络后可建立两个内部常驻节点、转移人口、调配公共服务班次，并以内部统合章程取得区域统合能力。统一国家仍未接入正式文字 UI。

## 2. 当前正在开发的阶段

**当前主阶段：R10 文字挂机验证层与第一阶段内容的试玩接入。**

当前优先验证的不是 3D/星球美术，而是：

1. 首阶段科技、工程、政策的前置、效果、自动续接与阶段门能否形成可玩闭环；
2. 持续挂机、LDU/核心指标、国策惯性、事件与完成报告是否让普通玩家读得懂；
3. 同一套内容 ID、工程效果和状态能否在未来空间层重新落到合格地理位置。

## 3. 尚未完善或尚未验收的部分

- R10 的实际试玩、数值节奏、文本可读性和“脱离生存危机”体验仍需用户验收；不能只以构建通过代替体验结论。
- R5/R6 的完整千级目录虽已生成并可校验，但玩家界面的分层浏览、搜索、已完成档案与阶段化呈现仍需持续完善。
- 地图现有生成和视觉仍未通过最终美术验收；R9 自然骨架是正确方向，但地球尺度、黑白骨架、地貌可读性、性能和视觉融合仍需反复验证。
- 文字挂机和地图空间层之间尚未完成正式回接：水坝、矿场、港口、道路等未来需要通过工程模块、候选地点、端点和路线规划落地。
- 战争、外交、统一国家、后期产业链、太阳系与星际阶段仍主要是设定/规格，未成为完整可玩系统。
- 多世界/多战役模板验证、长期离线结算、平衡测试、存档迁移、可访问性与最终 UI 整合仍未完成。

## 4. 文件之间的关系

```text
PRD.md（产品定位与性能约束）
  └─ CAMPAIGN_CHRONICLE.md（玩家/统一政府最高叙事约束）
       ├─ LORE.md（灾后世界与原始设定）
       ├─ TECH_MATERIAL.md（八游戏原始素材）
       │    └─ TECH_INTEGRATED.md（分类、断层、整合方向）
       └─ TIMELINE.md / NOVEL_OUTLINE.md / 各 ERA_EXPANSION.md（编年史与社会细节）

STANDARDIZATION_AND_SCENARIO_SEPARATION.md（系统与剧本边界）
  └─ SYSTEM_SKELETON_BLUEPRINT.md（世界、战役、内容、模拟、UI 总关系）
       ├─ GAME_SYSTEMS.md / GAME_DATA_SCHEMA.md（早期系统和数据规格）
       ├─ R5_*（科技、工程、政策目录与前置）
       ├─ R6_*（玩家文字规则与文案包）
       ├─ R9_*（星球自然骨架）
       └─ R10_*（当前文字挂机验证层）
```

## 5. 当前世界观发展阶段

世界观的全局叙事已推演到 2450 年终局；当前可玩验证聚焦于**第一阶段开端**：灾后共同体离开存续设施、建立聚居地、形成可维护的公共生活与初级区域网络。旧河谷是这一阶段的测试夹具，不是未来通用战役的唯一开局。

## 6. 当前重点问题

1. 将大规模内容目录变成清晰、分层、可读、可自动推进的玩家体验，而不是一千张卡片或隐藏的数据表。
2. 先通过文字挂机验证数值与因果，再回接星球空间层，避免为了摆放水坝/道路/矿场而提前把规则写死。
3. 固定“自然世界事实—工程模块—工程实例—视觉层”接口，确保地图改美术或换种子不会破坏科技/工程逻辑。
4. 继续清理河谷专名对通用数据与展示的耦合，但保留它作为独立夹具与叙事样例。
5. 统一玩家语言、信息层级和 UI 操作逻辑，减少缩略词、解释腔、重复面板与无效图层开关。

## 7. 下一阶段建议任务（不等于已经授权实施）

1. 对 R17–R20 进行第二轮实际试玩验收，记录探索节奏、发现前置、线稿动态、自动化、可读性与数值问题。
2. R23 起将文字战役从“区域统合”扩展到“统一国家”：先定义国家级行政、跨区网络和城市服务的阶段门，再接入相应科技、工程与政策；继续沿用发现、地点、工程、网络与国家内核契约。
3. 用多个世界模板和战役模板替换当前三条探索夹具，验证方向、地点质量与发展路径不依赖固定名称或顺序。
4. 在文字战役的统一国家阶段通过数值与因果验证后，才将工程模块回接 R9 候选地点、道路端点和空间 UI。
