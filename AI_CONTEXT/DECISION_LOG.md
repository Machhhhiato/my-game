# Always Game 项目决策摘录

## 2026-08-19

决定：每次提交并推送 GitHub 前，必须检查并更新相关 AI 上下文；功能、设定、状态、决策和实施导航必须同提交、同推送。通用规则写入根目录 `AI_COLLABORATION_RULES.md`。

原因：跨电脑和跨会话时，聊天并非所有工具都可读取；若代码与上下文分批推送，新终端会短暂或长期读取到不完整项目事实。

影响：`AGENTS.md`、`DOCS_INDEX.md`、顶层知识文件与本目录导航使用同一阅读入口；提交前必须明确区分计划、已实现、自动验证和人工验收。

> 本文件提炼根目录 `DECISION_LOG.md`、系统骨架和阶段规格中的长期有效决定。完整台账仍以根目录 `DECISION_LOG.md` 为准。

## 早期设定

决定：玩家扮演单一主权的大统合联邦中央政府，而非多个主权政体的协调者。

原因：项目需要体现统一调配、战略选择与挂机执行，而不是地方之间的松散博弈。

影响：军队、外交、货币、税收、人口登记、战略资源与国家计划必须由中央掌握；地方只能有限执行自治。

## 2026-08-15

决定：玩家负责方向、政策、科研、工程、安全与重大抉择，系统负责日常执行和后果。

原因：游戏定位是挂机战略，而非环世界式个体微操。

影响：不得以逐人分工、逐格建造、战术单位控制作为主循环；报告必须解释战略命令的物质与社会后果。

## 2026-08-15

决定：宏观编年史锚点固定，实现路径可变。

原因：既要保留完整世界发展主线，也要给玩家的科技抢跑、工业优先、军事扩张和空间冲刺留下差异化空间。

影响：玩家可改变年份、伤亡、联盟、社会结构和局部结果；系统不能把玩家强行拉回唯一“正确路线”。

## 2026-08-15

决定：主战役持续运行，不使用期末自动暂停或机械的月度确认循环。

原因：挂机感来自连续时间与持续反馈，玩家只在需要时调整方向。

影响：研究、工程、政策和普通事件应不停表；切换国家重点通过调度惯性体现成本。

## 2026-08-15

决定：长期资源层收敛为人口与九项核心国家指标；具体物资转为事件、工程投入、设施维护和地区特性。

原因：后期绝对资源量会膨胀且难读，核心指标更能表达国家状态。

影响：早期使用 LDU、国家阶段使用 NDU；UI 优先展示覆盖、储备时间、趋势和风险，不展示无限吨数。

## 2026-08-15

决定：玩家操作区分为国策、当前政策、工程和科研；工程/科研各有独立自动模式。

原因：旧“方向/法令/工程”混用使玩家看不出行动的时间尺度和实体结果。

影响：国策是长期倾斜，政策是短期行政行动，工程是实体项目，科研是能力验证；完成项目移出主选择区并归档。

## 2026-08-15

决定：每个历史阶段建立 1,000 科技、1,000 工程和 20 个可迭代政策家族。

原因：内容规模应支持长期挂机，但不能用孤立小加成凑数。

影响：科技、工程、政策必须共享前置与效果结构；政策须随科技/设施升级，而不是永远使用开局版本。

## 2026-08-16

决定：科技树采用主干突破、路线分支、能力分级的三层结构，且主干之间存在跨领域前置。

原因：真实发展依赖材料、测量、能源、教育、行政、交通和已运行设施的共同条件。

影响：下一层主干需要跨领域能力证明与工程验证；港口、远洋、道路、区域供水等不能只靠研究点解锁。

## 2026-08-16

决定：玩家文字由 Codex 负责规范和验收，DeepSeek 只可录入已冻结文本。

原因：玩家反馈表明自动生成文字容易出现缩略、解释腔和对象混淆。

影响：国策、科技、工程、事件、报告、锁定条件等必须使用不同说话者、字段与口吻；实现层不可自行补写文案。

## 2026-08-16

决定：河谷旧纵切降级为独立测试夹具，通用系统与剧本彻底分离。

原因：项目制作剧本是为补完世界和验证规则，不是把“第 07 号—翡翠河谷”硬编码成唯一游戏。

影响：显示名称不可作逻辑主键；世界模板、战役模板、内容目录、夹具、呈现层分开；新通用数据不得使用河谷坐标、项目 ID 或专名。

## 2026-08-16

决定：星球采用可存档、可重建的自然骨架，工程结果和视觉层分开。

原因：噪声贴图、固定屏幕坐标和镜头相关绘制无法为城市、道路、水坝、港口和随机战役提供一致逻辑。

影响：世界生成遵循“行星参数→地壳/海盆→构造→水文→气候→生态资源→玩家工程”；工程只在真实里程碑写入地图。

## 2026-08-16

决定：道路由需求和端点触发，而非自然世界预生成。

原因：道路需要明确起点、终点、标准、风险和施工条件，不能只画一条视觉线。

影响：路线规划读取球面邻接、坡度、水系、海陆、灾害、网络和技术；玩家可在多条可解释方案中选择或暂缓。

## 2026-08-16

决定：先以文字挂机验证科技、工程、政策与数值因果，再回接 3D/星球空间层。

原因：地图定位、工程选址、道路与资产美术会显著增加复杂度，不能阻塞核心挂机闭环验证。

影响：R10 先验证抽象工程的能力与效果；空间层后续根据同一 ID 和效果契约筛选合格地点、规划网络并写入地表。

## 2026-08-18

决定：玩家日期采用年—月—上/中/下旬；每旬包含十个后台日，1× 速度下一旬持续三分钟。

原因：早期需要足够观察、阅读和调整时间，但持续挂机、离线结算和日级因果不能退化为点击回合制。

影响：界面以旬为阅读、报告和政策节点单位；模拟仍按日结算，玩家无操作时国家继续运行。

## 2026-08-18

决定：工时分配是后台数据，玩家只查看并受制于人口、可调度人手、研究组、工务队和临时行动的编制占用。

原因：显示百分比分配会把战略游戏变成繁琐的劳工表；每日三次抢点征集又与真实挂机冲突。

影响：研究满足前置和研究人手即可启动；工程还需要建设物资和工务队。临时行动持续一个旬，自动化和设施通过减少基础维持人手释放发展能力。

## 2026-08-18

决定：保障储备必须有稳定、紧张、临界、失守的状态链；日历、人力、建设物资、临时行动、失败与每日效果归因均需可序列化。

原因：长期资源为零仍继续运行会破坏生存阶段的后果感，也无法解释国策、科技、工程和事件如何相互作用。

影响：失守会停止战役推进；后续详情和报告可从同一状态源说明项目、国策和行动的真实影响。

## 2026-08-18

决定：第一阶段所有科技、工程和政策版本都必须在内容目录中记录标准运行时字段：时间、编制、资源需求和结果；政策执行期间同样占用行政编制。

原因：若由 UI 或模拟根据名称、ID、卡片类型临时猜测工期、开工成本和效果，千级内容会在进入游戏后重新混在一起，无法独立调参、追溯或回接地图。

影响：R10 只消费目录的 `runtime` 合同。科技提供能力和解锁；工程消耗建设物资并形成设施效果；政策在有限期限内占用执行人员。平衡只调整数据字段，不改稳定 ID、前置图或玩家文案。

## 2026-08-18

决定：国家、城市、都市圈、设施、网络、势力、行动、效果、情报与历史使用统一数据语法；科技、工程、政策、外交与军事共享执行外壳但保留不同结果类型。

原因：后期内容不能为每一种玩法另建状态机；同时，城市和地区不能被误建模为独立主权势力，地图、UI 和剧本也不能直接修改国家事实。

影响：R11 成为 R9 自然骨架与 R10 文字挂机之间的通用运行时底座。接入必须通过稳定 ID、作用域、权责、生命周期、标准效果和因果账本；玩家情报与世界真实状态保持分离。

## 2026-08-18

决定：指标必须引用统一量纲目录并按发展阶段开放展示；起步共同体、统一国家、外交冲突使用同一国家内核的三个开发存档夹具。

原因：同一项数值若没有单位和展示阶段，会造成早期信息过载或后期把舰队、设施、航线压缩成无意义点数；单一开局夹具也无法验证国家和外交模块。

影响：早期 UI 不提前泄露舰队、NDU 或航天数据；后期不能把舰艇和设施压成点数。三个夹具用于结构、数值和 UI 回归，不构成正式剧情。

## 2026-08-18

决定：以统一国家开发夹具先验证“科技能力 → 实体工程 → 城市服务/国家运行 → 有期限政策”的纵切片，再批量扩展后期目录。

原因：后期内容若直接堆入科技表，容易重新混成抽象点数，也无法证明工程、城市、网络和维护在同一状态链中运作。

影响：科技前置可要求已运行设施或网络；工程完成必须写入设施或网络事实；城市服务按城市作用域存储；R12 的 30 项定义只作内核回归，不能被误称为正式国家战役内容。

## 2026-08-18

决定：外交与军事纵切片必须继承国内设施、网络、维护与行政事实；舰队保留精确可数资产，外交行动只通过关系与情报状态产生影响。

原因：若把舰队、战备、补给和外交写成脱离港口、工务、通信与制度的独立数值，后期国家模拟会退化为互不相干的面板。

影响：舰艇维修、传感网、指挥通信、护航与核查会谈形成“国内能力 → 外部行动”的前置链；危机不会因信任上升自动消失，仍需要后续战争/外交系统结算。

## 2026-08-18

决定：首阶段试玩界面必须从运行时事实生成“当前处境、下一步与检查项”；记录只呈现研究/工程完成、保障风险、恢复和阶段达成等重点变化。

原因：持续挂机不能要求玩家从日报或隐藏数据反推该做什么。阶段提示必须帮助决策，但不能替代模拟或把数值结论写死在剧情文案中。

影响：R16 的引导层不保存独立剧情状态，也不引用河谷等剧本专名；未来战役可替换阶段门槛，仍复用同一信息呈现契约。

## 2026-08-18

决定：探索是科技与地点工程之间的事实层。探索完成先写入研究线索和带稳定地理引用的工程候选地；研究和工程只读取这些前置，不从 UI、显示名称或剧本坐标推断。

原因：文字挂机阶段必须先验证“发现—理解—建设”的因果；未来水坝、矿场、港口和道路也需要同一地点事实回接星球迷雾、候选选址和施工实例。

影响：R17 首阶段以三个方向夹具验证该链条。它们的坐标引用只用于试玩世界，不构成正式行星地图；正式战役须由种子和自然骨架生成候选地点。

## 2026-08-18

决定：R18 的文字战略图只表达已知范围、方向、路线和节点状态；展示坐标不能作为工程、道路或地图事实。R20 用多路线模拟检查探索前置与国策代价，而不是把一条最优路线写成正史。

原因：空间画面尚未通过自然骨架与性能验收，但玩家已需要理解“向哪里探索、发现了什么、这会解锁什么”。同时，科技/工程/政策的价值必须在不同顺序下仍可验证。

影响：回接空间层只能消费发现记录中的稳定地理引用；R21 的区域网络和统一国家阶段必须复用同一发现、地点、工程和国家内核契约。

## 2026-08-18

决定：稳定聚居达成后，文字战役将迁入单一玩家政体的国家内核；迁移保留人口、时间、保障、建设储备、能力和设施，不能用另一份预制国家存档替换玩家历史。

原因：如果“聚居地”与“国家”各有一套不相通的状态，科技、工程和探索的前期选择会在中期失去因果，也无法验证统一国家来自怎样的积累。

影响：R21 先以“勘察→中继→补给线→协作章程”验证区域网络的最小可玩链；区域统合和统一国家仍需在该内核上逐步增加多节点、人口流动、服务统筹与阶段门。

## 2026-08-18

决定：区域统合阶段中的新节点必须以城市对象、人口转移和服务量纲记录；不能用普通事件文本或预制第二势力代替。

原因：城市、人口、服务与网络是未来道路、医院、学校、港口和都市圈的共同引用点。若此处只写剧情，后续空间回接会失去稳定 ID 和可验证因果。

影响：R22 用两个通用常驻节点和有限服务班次验证数据链；其初始成本只用于纵切片可达性，不能被误认为长期平衡数值。

## 2026-08-18

决定：统一国家阶段必须由同一政体内的跨区登记、可维护行政设施、端点明确的物流网络、有期限的公共服务程序与统一章程共同构成；政体转型是可追溯的国家内核事实，而不是剧情切换。

原因：区域统合若直接换成预制国家或单一阈值，前期发现、工程、人口与服务选择将失去因果，也无法验证单一主权中央政府的执行成本与社会认受性。

影响：R23 将以行政区域和政体档案的通用效果扩展国家内核；地方仍只是同一政体下的执行与反馈单元，不拥有独立外交、军队、货币、战略资源或退出权。空间地图、外部势力、战争和长期平衡不在该纵切片范围内。

## 2026-08-18

决定：公共服务保障令在统一国家纵切片中只作为有期限的服务保障程序运行；它完成后留下可追溯的服务责任能力，而不留下永久的覆盖数值加成。

原因：政策若把临时调度直接写成永久百分比，会掩盖人员排班、设施维护和网络条件，且无法表达保障令结束后的实际服务回落与后续治理责任。

影响：R23 每日将既有城市服务覆盖拉向保障标准，政策结束后日结算再次按实际服务班次收敛；模拟必须证明该回落，同时保留统一登记和服务责任这两项制度事实。

## 2026-08-18

决定：首阶段探索须由初勘、条件满足后的复勘和可选研究—工程支线构成；勘察过程可以报告有限现场进展，但只有完成后写入知识线索或工程候选地。

原因：一次性三选一探索不足以形成可持续的发现玩法；但把日常进度直接当作资源奖励又会破坏“发现→理解→建设”的事实链。

影响：R24 的复勘继续使用稳定发现与地理引用，依次解锁水源观测、前置补给或维修转存等可维护设施。它们不成为稳定聚居的强制门槛，也不授权提前回接空间地图。

## 2026-08-18

决定：临时征集必须在下达时明确受理、人员占用、持续时间和下一日结算影响；征集材料还须进入建设物资的日生产链。

原因：持续行动如果只在日结算后才有模糊变化，玩家会误以为按钮失效；材料征集若不影响建设物资，也无法解释其与工程启动之间的关系。

影响：同一时间只允许一项临时征集，材料征集提高建设物资日产出，但不绕过日常消耗、人员占用或设施化的长期条件。

## 2026-08-18

决定：文字战役模板只拥有探索目标的呈现、稳定地理引用、坐标与发现放置；科技、工程、政策及国家内核使用跨模板的能力契约。存档必须记录模板身份，旧默认试玩存档迁移到默认模板。

原因：如果探索方向、名称、显示坐标或测试候选地直接成为逻辑前置，替换剧本时会悄悄改变研究、工程和统一国家的可达性，且会把当前夹具误当作世界设定。

影响：R25 保留默认试玩并增加不同 ID、布局、地理引用和探索顺序的山脊验证模板；两套模板可复用同一发现/能力 ID，但这些 ID 不表达地点名称或坐标。空间层仍不得读取文字模板的显示坐标。

## 2026-08-18

决定：R26 将把探索、人口与势力成长作为同一条因果链开发。探索的物资、幸存者、路线和外部接触都必须带来源、成本、风险与后续条件；人口增长必须同时带来劳动力与供给/住房/服务压力。后期国家测试存档与实力面板只作独立开发入口，不改变默认开局。

原因：试玩反馈显示，单一的“探索换科技/工程前置”、固定人口和少量物资，不能让玩家感到共同体已从求生队伍成长为可治理、可防卫、可选择未来的国家。

影响：不得用随机资源包、无代价人口或单一战力分数伪造发展感。显示层需要把技术、生产、社会、政治与日常生活的连续变化说清；军事只在人员、装备、训练、补给和指挥条件具备后作为可验证能力出现。

## 2026-08-18

决定：R26-A 的幸存者探索结果只生成待接纳群体；接纳必须先满足住处/公共服务容量及饮水、食物储备。打捞是一次性物资事实，前哨是稳定路线事实，均不直接变成永久生产加成。

原因：人口、物资和路线若在探索完成时免费、生效且永久化，会重新把探索退化为随机奖励按钮，掩盖共同体为新居民和外围活动承担的生活、维护与治理成本。

影响：接纳后每日储备消耗按人口比例变化，且被抚养者同步增加；后续出生、健康、迁出和前哨维护必须接在同一人口/路线事实之上，不得另起隐藏计数器。

## 2026-08-18

决定：搭建临时安置棚、整理场地等基础生活工程只要求已勘察的工程候选地、劳力和建设物资，不以科研作为门槛；科研只门控保藏、供水流程、维修和自动化等需要可复制知识的专业能力。

原因：把常识性搭建也做成研究结果，会切断“探索到地点后立即改善生活”的行动反馈，并使新增人口看起来挤掉了全部科研和工程。

影响：项目合同新增住房容量字段，由工程实际提供接纳空间。UI 在研究/工程暂无可执行项时必须展示下一步条件，避免把等待误呈现为系统消失。

影响：进入测试页不会迁移或替换聚居战役存档。摘要只读取国家内核已有量纲/对象；后续扩展必须让每一项变化仍可回溯到具体设施、网络、服务班次或装备。

# 2026-08-18：统一国家开发存档的玩家入口必须复用文字战役的时间、操作、档案和视觉外壳；Nation Kernel Inspector 只作为明确隔离的开发核对工具。原因是后期若切换到独立检查器，玩家会失去从聚居、网络到统合的连续发展感。影响：`?kernel=unified` 显示连续国家战役测试页，`?kernelInspector=unified` 显示原始核对器；实力摘要必须带有日常生活结果，不能形成新的抽象战力或固定剧情坐标体系。
